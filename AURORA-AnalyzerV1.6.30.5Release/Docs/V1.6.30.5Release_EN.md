# AURORA-Analyzer V1.6.30.5 Release Notes

## 1. Welcome to V1.6.30.5

Thank you for choosing AURORA-Analyzer! V1.6.30.5 is a focused polish release across three dimensions: **motion rhythm uniformity, shell architecture consistency, and startup flow streamlining**. We have fully modernized the motion system — three-track decoupling, dual-pace recipes, global rhythm coordination — letting you freely switch between "graceful elegance" and "efficient speed". We have reorganized the entire shell into a unified glass aesthetic, with button groups, settings panel, and exit-confirm panel all using the same material and motion language as the system. We have removed redundant startup rituals while preserving the ceremonial feel — Splash is followed by your work console. We also systematically fixed 16 issues from the UI/UX Audit Report (10 fully fixed + 6 partial/infrastructure) and the core rulings of the Modern Dynamic Response & Spatially-Decoupled Motion System Architecture Technical White Paper. MSBuild compiled zero errors zero warnings, works out of the box.

This update revolves around four directions: **modernized motion experience**, **unified shell architecture**, **streamlined startup flow**, and **systematic UI/UX defect fixes**.

## 2. More Modern Motion Experience

### Your Choice of Motion Pace

V1.6.30.5 introduces "Graceful / Fast" dual-pace recipes. **Graceful** fully restores the old "calm 1.15→1.0 container overshoot + buttons one-by-one graceful landing + starfield 2.2-second depth traversal" aurora ritual — the long-polished motion assets were not sacrificed. **Fast** shrinks the whole rhythm to about 1/3 (container 450ms, simultaneous buttons, starfield 0.9 seconds), for focused work scenarios. Switching pace takes effect on the **next view transition immediately**, no app restart needed.

### Your Control over Transition Interruptibility

New clicks during navigation transitions are no longer "ignored" — new navigation immediately overrides the old transition, the old entrance/exit animations are taken over by the new one. If you find the "page goes to where I clicked second" behavior confusing, you can also turn off this switch, letting all clicks during transitions be ignored until the transition completes.

### Your Savings on Startup Ritual Tax

Before V1.6.30.5, every startup went through the full Splash → Language → Mode → Work View sequence. From V1.6.30.5, you can enable "Quick Startup" — next launch skips the Language page and goes directly to the Mode Selection page (View 2). The Splash brand ceremony is preserved, only the repeated language selection is removed. Mode selection remains in your active control — every launch you can choose Smart / PRO / Console mode according to the situation.

### Starfield Depth No Longer Kidnapped by Transitions

Starfield depth traversal is the soul of AURORA's ceremonial feel, but the old version bound the motion and starfield duration to the same total budget — fast container entrance, starfield also compressed to "teleport". V1.6.30.5 decouples the container entrance, starfield parallax, and view switch into independent timelines: UI transition ends, starfield continues to slowly slide through the remaining depth — longitudinal continuity preserved, every view switch clearly shows the starfield traversal process.

### Every Motion Corner Stays Consistent

Button entrance, glass popup, dialog traversal, settings panel fade-in/out — all these originally scattered motion durations now uniformly link to your pace selection. "Fast here, slow there" is a major no-no for rhythm uniformity. V1.6.30.5, through a "Global Scaling Tool", lets every operation feel the same rhythm while preserving visual style consistency.

## 3. More Unified Shell Architecture

### Top-Right Unified Settings & Exit Button Group

The settings button migrated from bottom-right to top-right, with a new ✕ exit button beside. Both buttons are 36×36 large hit areas (meeting touch standards) with accessibility names for screen readers. The whole button group **only shows on the Mode Selection state** — it immediately hides when entering Smart / PRO mode, history views, or dialog views, avoiding persistent interference.

### Glass-Style Settings & Exit-Confirm Panels

The new settings and exit-confirm panels are shell-internal glass overlays, using the same form and material pipeline as other glass dialogs (Solution Detail, message layer, etc.). This means the panel background directly shows the starfield and main window content, and the buttons grow from the click position (grow from wherever you click), aligning with modern operating systems' "content grows from touch point" intuition.

### Exit Gets an Extra Layer of Protection

The top-right ✕ exit, and the exit buttons in Smart / PRO mode, now all pop up a "Are you sure you want to exit? Confirm / Cancel" glass panel. Cancel does nothing; Confirm goes through the original exit animation → shell exit animation → process exit flow. Avoid the cost of accidental clicks.

## 4. More Considerate Startup Flow

### Preferences Saved in App Directory

The preference file originally hidden under `%LOCALAPPDATA%` is now placed in the exe-same-level directory (e.g., `Wpf\user-preferences.txt`). As open-source software, you can see at a glance where your preferences are saved and modify them anytime — preferences are "transparent".

### Remember Your Language

On next launch, if you previously selected Chinese, you'll see the Chinese interface; English for English. No need to switch every time. Mode selection is still actively decided by you at every launch.

### Faster Startup

With the "Quick Startup" option enabled, from double-clicking the exe to being able to select a mode, V1.6.30.5 removes the intermediate language selection step — Splash is directly followed by the Mode Selection page. If this is your first launch (no preference record), the full flow is still used; necessary settings won't be skipped.

### Command-Line Direct Access Still Available

If you want to skip mode selection and go directly to a specific mode, you can still use the `--mode smart` / `--mode pro` / `--mode console` parameters. This is the professional user's channel, completely independent from the regular double-click experience.

## 5. Smoother Interface Switching & Misclick Prevention

### Navigation No Longer "Stuck"

Before V1.6.30.5, every view switch required waiting 2.6-2.9 seconds for the animation to complete before responding to your next action — input black hole. Now during a switch you can click any new target at any time, the old switch will be overridden by the new one. A "motion token" mechanism is also introduced: each animation in the orchestration chain checks the token before playing, expired ones automatically abandon — rapid switching leaves no residue or stutter.

### Sweep Light No Longer "Trailing Flash"

The old version's tilt sweep light triggered by mouse hover would let every button leave a 2.4-second trailing flash when you quickly swept across a row of buttons. V1.6.30.5 now requires hover to persist ≥120ms before triggering sweep, and mouse leaving triggers immediate 80ms fade-out stop — clean and crisp on quick sweeps, no more trailing.

### System Reduce-Motion Takes Effect Immediately

If your Windows system has "Reduce Motion" enabled (accessibility option), V1.6.30.5 responds immediately when you change system settings — no AURORA restart needed. Combined with the in-app "Fast" pace, animations can be compressed further, suitable for vestibular-sensitive users.

## 6. More Consistent Visual Details

### Button Color Single Source of Truth

The old button glass base color was defined in three places (theme file, native style, inside AuroraButton), one change required syncing all three or drift would occur. V1.6.30.5 converges the button glass base color to a single source of truth in the resource dictionary — color changes at one place, takes effect globally.

### Clear Without Blur on High-DPI Screens

The new version enables window-level layout rounding (1px hairline highlights no longer blur under DPI scaling) and adds the PerMonitorV2 manifest (the program can sense you plug/unplug different DPI displays and adjust in real time). Skeleton screen base styles are also ready — list loading no longer "content jumps", but has Shimmer placeholder transition.

### Glass Dialog Material Unified

V1.6.30.1 unified the inline animation implementations of glass popups into one utility class. V1.6.30.5 further extends "click-point expansion" (when you press a button, the panel expands from the button position) to all glass overlays — Settings, Exit Confirm, Solution Detail, etc — — visual consistency at max.

## 7. More Friendly Accessibility Details

### Screen Readers Can Read It

Buttons automatically expose to screen readers, keyboard Tab focus has visible warm-gold glow, primary status text uses "polite mode" (screen reader announces without interrupting you). Each toggle in the settings panel has clear bilingual names.

### Touch Friendly

Shell buttons are 36×36 large hit areas (meeting Windows touch standards), easier to tap than default 28×28. The hover/press feedback of the settings/exit button group is also consistent with the main buttons.

### Esc Closes Dialogs with One Key

When any overlay is open (Settings, Exit Confirm, message layer), pressing Esc closes it. The shell-level global shortcut key pipeline ensures this behavior covers all panels — no more "stuck, can only click the top-right ✕" dialogs.

## 8. Systematically Fixed Defects

V1.6.30.5 systematically solves 16 issues from the UI/UX Audit Report:

**Fully Fixed (12)**:
- **Navigation transitions cannot be interrupted**: From 2.6-2.9 second input black hole down to ≤900ms (Graceful) / ≤280ms (Fast), and new navigation can override old transitions
- **Each button redraws per frame**: All buttons unified by a single frame loop scheduling, zero overhead for static buttons
- **Startup ritual tax**: Only persist language, jump directly to mode selection page
- **Global shortcut key system**: Shell-level PreviewKeyDown unified Esc/Backspace/Alt+←
- **Screen reader semantics**: Buttons auto expose + primary status LiveSetting
- **Native button contrast**: Switch to AuroraButton to solve contrast issue
- **Sweep light no intent detection**: Hover ≥120ms to start, MouseLeave 80ms fade-out stop
- **Reduce-motion read-once**: Subscribe to system event subscription changes for real-time reassessment
- **Touch targets**: Shell buttons 36×36
- **Exit hard-reset flashback**: Remove hard-reset block, read current animation values for handoff
- **Click-point expansion**: All glass overlays anchor transform origin to click position
- **Parallax duration mismatch**: From hard-coded 2700ms to read recipe independent track

**Partially Complete (6)**:
- **Design tokens paper-only**: This release did scattered font size corrections, gatekeeping and TypeScale follow-up
- **Velocity inheritance**: VelocityTracker infrastructure built, call-site integration follow-up
- **Button color triple source**: Single source convergence done, ShaderEffect name-reality matching follow-up
- **Skeleton screen + DPI**: Skeleton screen base styles + DPI done, PerMonitorV2 done
- **High-contrast mode**: Runtime reassessment done, pure-color theme switching follow-up
- **Token gatekeeping**: As future iteration
