## Part B 之前先说结论（TL;DR）

1. **现状定位：L1「辅助」级**。SmartEngine 是固定四阶段流水线（环境感知→日志提取→知识库碰撞→修复终端），决策方式是**静态规则查表**（EventID+Source+关键字 → 规则 → 命令），205 条规则/503 条命令的知识库只被当作"字典"用；每条非 auto 命令都要用户点菜单+弹授权。README 承诺的"一键诊断+一键修复"，代码现实是"列表诊断+逐项修复"。
2. **离自主最近的一块短板不是"更多智能"，而是"验证闭环"**：执行修复后从不复测——"验证通过已修复"只是一段 UI 文案（`Aurora-SmartEngine.ps1:1066-1071`），知识库 schema 里根本没有 post_check 字段。**没有验证的自主等于盲飞**。这是整条路线的第一优先级。
3. **底座比预期扎实**：撤销快照（注册表/文件/服务三类，磁盘检查+原子写入）、系统还原点、方案级失败策略（Abort/Continue/AskUser）、历史指纹（0.7 阈值匹配）、报告 diff（resolved/degraded 语义）、安全沙箱（60 条黑名单正则+审计日志）、双向心跳——自主化所需的"安全气囊"已经大半就位，缺的是把它们串成闭环的"驾驶员"。
4. **路线图一句话**：Phase 0 补安全地基（回滚覆盖率 4.6%→80%）→ Phase 1 建验证闭环（修完必复测）→ Phase 2 一键自动巡航（小白一键，Low/Medium 类全自动）→ Phase 3 编排与感知广度 → Phase 4 数据飞轮 → Phase 5 守护形态（可选本地 LLM 顾问，只解释不执行）。

# Part B · 智慧赋能规划（自主能力路线图）

## B0. 北极星与"五自"拆解

**北极星**：新手用户从「打开工具」到「问题被解决并验证」，全程只需**一次知情确认**；过程中工具用小白听得懂的语言叙述自己在做什么；任何时刻可暂停/接管/撤销。

| 能力 | 定义 | 现状 | 终态 |
|---|---|---|---|
| 自主检测 | 无需用户指定查什么，工具自己决定采集什么 | ◐ 事件日志+Minidump 自动采集，且有时间窗口智能（48h 崩溃→2h 靶向）；但服务/磁盘/网络/启动项不主动扫 | 多信号感知层，按上下文动态选择采集面 |
| 自主分析 | 把零散信号串成"发生了什么、为什么" | ◐ 知识库查表匹配（205 规则），causes/solutions 仅作展示不参与决策 | 证据链推理 + 置信度 + 因果叙述输出 |
| 自主排查 | 主动缩小范围、多步求证 | ✗ 单轮碰撞，无多轮排查 | 假设-验证循环（修→测→再定位） |
| 自主修复 | 决定怎么修并执行 | ◐ 六步沙箱执行器成熟，但每步等用户点击 | 计划编排 + 风险分级自动执行 |
| 自主解决 | 修复 + **验证** + 确认不复发 | ✗ 完全缺失（无 post_check/复测） | 闭环：修→验→不通过则换方案/回滚→升级人工 |

### 六大缺口（按对自主化的杀伤力排序）
1. **无验证闭环**：503 条命令 0 条 post_check；pre_check 全部是 `$true` 占位；修完只打 ✓ 不复测。
2. **无编排**：规则间无依赖/冲突/顺序模型，只有 priority 排序展示；不能形成"先还原点→再服务→再驱动"的计划。
3. **风险与授权脱钩**：授权门槛只看 `auto_execute` 布尔（103/503）；risk_level 只影响 UI 颜色；KB 中 Critical 命令 0 条——3 秒确认防线空转。回滚覆盖率仅 **23/503（4.6%）**。
4. **决策是查表不是推理**：causes/solutions 知识在库里沉睡；匹配无置信度语义（WPF 侧 0.5/0.2/0.3 加权有分数但未用于授权决策）。
5. **感知面窄**：只有事件日志+Minidump 两条感知通道；服务/启动项/磁盘/网络状态仅作为"修复命令"被动存在。
6. **无学习回路**：每次会话的"修了什么、有没有用"不回流；历史指纹只用于"以前见过吗"，不用于策略改进。

## B2. 自主等级模型（L0–L5）

| 等级 | 名称 | 特征 | 现状/目标 |
|---|---|---|---|
| L0 | 手动 | PRO 模式：17 阶段流水线，人读报告人决策 | ✅ 已有 |
| L1 | 辅助 | 检测+推荐+逐项人工执行，每条授权 | ✅ **现状**（SmartMode） |
| L2 | 部分自主 | 安全类（可逆+低风险）自动执行，其余人工 | ◐ 部件已有（103 条 auto_execute + FixExecutionService 串行执行能力），缺验证与策略 |
| L3 | 有条件自主 | **闭环**：计划→执行→验证→失败自动换方案/回滚→报告；批量确认一次 | Phase 2 目标 |
| L4 | 高度自主 | 多信号感知+规则编排+多轮排查；仅 Critical/不可逆请求人工；带学习回路的策略调优 | Phase 3–4 目标 |
| L5 | 守护 | 常驻/定期自主巡检、主动预警复发、（可选）本地 LLM 顾问解释层 | Phase 5 探索 |

**关键设计原则：自主性 = f(风险 × 可逆性 × 置信度 × 历史效能)，四维全绿才放行**。任何一维不足就降级为"推荐+人工确认"。自主等级不是全局开关，是**逐命令判定**。

## B3. 目标架构：六层能力环 + 三道防线

```
┌─────────────────────────────────────────────────────────┐
│  感知层 Perception    事件日志│Minidump│服务│启动项│磁盘│网络│驱动  │
│       （新增 Detector 插件式模块，输出统一 Signal 池）        │
├─────────────────────────────────────────────────────────┤
│  诊断层 Diagnosis     规则匹配(现有双索引) + 证据聚合 + 置信度  │
│                       + causes/solutions 因果叙述（唤醒沉睡知识）│
├─────────────────────────────────────────────────────────┤
│  决策层 Planning       PlanBuilder：规则 DAG（依赖/冲突/顺序）  │
│                       AutonomyPolicy：四维自主性判定 → 执行分级  │
├─────────────────────────────────────────────────────────┤
│  执行层 Execution      现有 SafeAction 六步沙箱（保持不动）      │
│                       + 命令级快照 + 失败三策略 + 替代方案重试     │
├─────────────────────────────────────────────────────────┤
│  验证层 Verification   post_check + 窄窗复扫 + resolved 判定     │
│                       不通过 → 换方案/回滚/升级人工（全新建设）     │
├─────────────────────────────────────────────────────────┤
│  学习层 Learning       OutcomeRecord 落盘 → 规则效能库 → KB 调优  │
│                       历史指纹 → 复发检测（全新建设）             │
└─────────────────────────────────────────────────────────┘
三道防线：① 执行前 快照/还原点（现有） ② 执行中 黑名单+审计（现有）
         ③ 执行后 验证门+自动回滚（新建，Phase 1 核心）
```

**授权阶梯**（谁决定执行）：
- **自动执行**：risk ≤ Medium ∧ 有快照或回滚命令 ∧ 匹配置信度 ≥ 0.6 ∧ 历史效能 ≥ 0.7
- **批量确认一次**：High 风险但可逆——展示完整计划，一次同意执行整组
- **逐条人工**：Critical / 不可逆操作（格式化、删除无备份、BIOS/固件类）——**永远不自动**，保留 3 秒确认
- **禁止**：黑名单命中（现有 60 条正则继续兜底）

## B4. 数据飞轮设计

**OutcomeRecord（每命令一条，JSONL 追加写 `UserLogs\outcomes\`）**：
```
{ ts, sessionId, ruleId, commandId, matchScore(置信度), risk,
  snapshotId?, executed: true/false, exitCode, durationMs,
  postCheckPassed?, rescanResolved?,      // Phase 1 起
  alternateTried?, rolledBack?, escalatedToHuman?, userIntervention? }
```
- **规则效能库**：`eff(命令) = verified_resolved / executed`（90 天滚动窗）。eff < 0.5 → 自动降权 + 进人工审核队列；eff ≥ 0.9 且风险低 → 候选提升自主等级。**知识库从静态字典变成有统计生命的系统**。
- **复发检测**：历史指纹（现有 0.7 阈值匹配）复用为"上次修过的问题又出现了"——主动提示 + 关联上次 OutcomeRecord（"上次用命令 X 解决，本次建议直接执行"）。
- **未匹配聚类**：高频落网事件（不命中任何规则）定期聚类成"新规则草稿"供人工入库——KB 增长从手写变成有数据依据。
- **完整性前提**：OutcomeStore 与 TechData.json 纳入 `GAURORA.CHK.ENC` 哈希白名单（防飞轮投毒），自主路径启动前强制校验。

- **AuroraAgent 独立进程**：计划任务/常驻低频巡检（进程隔离，崩溃不伤壳；沿用 syncHash 协议经验但走 IPC）。此前维持进程内 RunspacePool 不动——零 IPC 开销是现在的心跳/取消可靠性来源。
- **可选本地 LLM 顾问**（明确边界）：**只做"日志→人话"翻译与方案解释增强，永不直接产出执行决策**——决策仍走规则+策略引擎（确定性、可审计）。默认离线本地模型，数据不出本机；在线 LLM 不默认开启。
- 自然语言问答（对已归档报告/修复历史提问）。

## B6. 面向小白的体验设计原则（自动巡航模式）

1. **一次知情，全程叙事**：开场一张同意卡讲清边界；过程中控制台用小白语言直播（"我发现网络组件最近报错 37 次，这通常由 X 引起，我正在用安全方式修复，修改已备份可撤销"）。
2. **透明可追溯**：每一步的 pre/post check 结果、快照 ID、审计日志（command_audit.log）在完成报告里可点开——**信任来自可验证，不来自形容词**。
3. **人类接管点常在**：任何时刻"暂停/接管"；失败自动回滚后明确说"我没把握，需要你决定"，并给出建议项。
4. **仪式感分层**：日常自动修复克制（进度+轻量确认）；**完全自主解决**时给高光时刻（全绿 HUD + 完成模态 + 自主解决率徽章）——呼应审计 R7 预算表。
5. **绝不静默做危险事**：Critical/不可逆永远逐条人工 + 3 秒确认；提权永远人工（整进程重启的现有机制不变）。

## B7. 关键技术决策点（已定建议）

| 决策点 | 建议 | 理由 |
|---|---|---|
| 验证闭环放引擎还是 C# | **C# 统一 VerifyService**，SmartEngine 与 FixExecutionService 双路径都调它 | SolutionDetail（C# 路径）与 SmartMode（引擎路径）共用一套验证语义，避免双实现漂移（教训：模态对话框双实现已漂移） |
| 进程模型 | Phase 0–4 维持进程内 RunspacePool；Phase 5 才拆 Agent | 心跳/取消/授权唤醒在进程内已被验证可靠；过早拆进程会引入 IPC 复杂度 |
| LLM 引入 | Phase 5 可选、本地优先、**只解释不执行** | 决策必须确定性可审计；LLM 幻觉不能碰注册表 |
| 知识库演进 | 数据驱动半自动（B4），人工审核入库 | KB 已有完整性信任链，投毒风险必须堵在入库口 |

## 结语

README 里写下的愿景——"把看似毫无关联的事件串联成完整的因果关系链，告诉用户到底发生了什么、应该如何修复"——今天的代码兑现了前半句的骨架（205 规则的双索引碰撞），后半句还停在"列表 + 逐项点击"。这份规划不做任何推翻重来的事：**六步沙箱、撤销体系、指纹、报告 diff、信任链全部保留**，要补的是把它们闭环的那根线——验证、编排、策略、学习。当 Phase 1 落地的那天，"验证通过已修复"这七个字第一次变成真的；当 Phase 2 落地的那天，小白用户只需要点一次"开始"。这就回到了初衷。
