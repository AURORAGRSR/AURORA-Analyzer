# AURORA-Analyzer V1.5.29.1 Release Notes

***

## 1. Welcome to V1.5.29.1

Thank you for choosing AURORA-Analyzer! V1.5.29.1 is a "depth visual expressiveness and switching robustness" refinement release. We introduced a meteor-style halo trail for starfield depth motion, so every view switch shows a vivid sense of direction; fixed the issue where controls flashed back to their original position during quick switching; and reallocated view depths so every click has visible depth feedback.

***

## 2. More Stable Quick Switching

### Goodbye, Flashback to Original Position

Fixed the issue where, during repeated switching between Pro mode, History mode, and Smart mode dedicated views, clicking an already-entered switch button before the animation finishes caused controls to suddenly flash back to their original position. The root cause was that entrance animation timers still fired after the exit animation started, overriding the exit state. V1.5.29.1 uses a unified `_pendingEnterTimers` tracking list to manage all entrance timers, uniformly canceling them before the exit animation starts, ensuring smooth switching without flashback.

All 6 views (Pro mode, Smart mode, History mode, Solution Detail, Permission dialog, Session Restore) have been fixed.

***

## 3. More Prominent Starfield Depth

### Star Enlargement and Brightening

We increased the star Size coefficient from 0.8 to 1.1 (~37% overall enlargement) and the BaseAlpha upper limit from 130 to 180, making stars more prominent and eye-catching during depth motion. We also reduced the transparency dimming coefficient from 0.62 to 0.25 — previously, star brightness was cut by nearly two-thirds during parallax; now brightness recovers to 75%, making the starfield shuttle feel clearly visible.

### Parallax Parameter Balance

Parallax parameters went through multiple rounds of tuning, finally settling on balanced values: push displacement 0.30, scale 0.45, preserving the in-your-face feel while avoiding excessive impact. The overall motion is softer and more elegant than V1.5.29.0.

***

## 4. More Vivid Meteor Trail

### Meteor-Style Halo Trail

V1.5.29.1 introduces a meteor-style halo trail for starfield depth motion — during parallax, near-field stars drag a gradient halo tail, with the transparent end at the tail and the bright end at the head. The direction follows the motion direction: zoomOut points the tail toward center (stars come from center), zoomIn points the tail outward (stars come from outside).

Trail length is driven by normalized velocity, so a consistent peak trail is visible regardless of span size. The trail naturally shortens with velocity decay ("retracts"), and disappears immediately when parallax ends, with no residue.

### Smooth, Flicker-Free

Trail length is smoothed by EMA exponential moving average, eliminating length flicker caused by inter-frame jitter; the soft-threshold transition eliminates hard-cut flicker when the trail appears/disappears. The overall visual is vivid and natural, with no abrupt jumps.

***

## 5. More Balanced Depth Hierarchy

### Peer View Depth Spread

V1.5.29.0 piled all 5 dialog/detail views at the same depth, so mutual switches had no depth feedback at all. V1.5.29.1 reallocates depths: History mode 0.70, Undo Viewer 0.78, Permission dialog 0.82, Session Restore 0.86, Solution Detail 0.95. Now peer switches like History→Detail, History→Undo, and Permission→Session all show visible depth motion — every click has feedback.

***

## 6. Smoother Admin Startup

### Fixed Admin Path Teleport

Fixed the starfield teleport issue when the admin path (elevated process) goes directly from Splash to the main window. The root cause was that the admin path skipped the permission dialog, leaving an insufficient parallax span. V1.5.29.1 adopts a pre-parallax scheme — first lets the starfield run alone for 500ms to dash to a middle depth, letting the user clearly perceive starfield motion, then starts Splash exit and main window entrance. Now the admin path startup is as smooth and natural as other paths.

***

## 7. More Reliable Mode-Switch Console Echo

### Fixed Console Not Echoing and Progress Stuck

Fixed the issue where, after returning from Smart mode to the main window and then entering Pro mode, the console did not echo at all and progress was stuck at 50%. The root cause was that polling startup missed resetting the `_pollingSuspended` flag, causing all polling callbacks to be directly skipped — logs, progress, and completion signals were all left unprocessed. Users had to click "Force Stop" before console content would surge in all at once.

Also fixed multiple related issues: console content "flashing then disappearing" (caused by async clearing timing error), cross-thread logs not updating (caused by loose thread check), and timer being starved by rendering (async dispatch occupied and deferred by Render). Now the console echo after mode switching is real-time and reliable.

***

## 8. More Stable Engine Invocation and Progress Convergence

### Fixed Assert-AuroraLaunchContext Error

Fixed the issue where running Pro Mode first, then terminating it and running Smart Mode produces a "command not found" error. The root cause is that the smart engine lacked a function-existence check, and Runspace reuse caused the function definition to be lost. V1.5.29.1 aligns the smart engine with the pro engine's defensive call pattern — it now checks Get-Command for function existence before calling Assert-AuroraLaunchContext, avoiding the command-not-found error caused by Runspace state pollution.

### Fixed Probabilistic 50% Progress Stuck

Fixed the issue where, when the smart engine completes very quickly, progress could randomly get stuck between 50% and 100%. The root cause is a polling sampling timing issue when the engine completes instantly — the poll samples Progress=50, then the engine completes and sets the completion signal, but if the running flag has already been reset by another path, the completion handler is not called and Progress=100 is never set. V1.5.29.1 now forces Progress=100 when the completion signal is detected, regardless of the running state.

### Hash List Sync

After the script modifications above, the integrity-check hash list has been synced to match the updated LaunchGuard.ps1 and SmartEngine.ps1 files, preventing false integrity-check failures from forcing the smart engine to exit.
