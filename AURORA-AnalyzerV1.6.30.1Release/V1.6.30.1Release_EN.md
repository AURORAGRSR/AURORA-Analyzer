# AURORA-Analyzer V1.6.30.1 Release Notes

***

## 1. Welcome to V1.6.30.1

Thank you for choosing AURORA-Analyzer! V1.6.30.1 is a "execution flow robustness and rollback closure completeness" hardening release. We rebuilt the execution window of the Solution View to make every repair step clearly visible, completed a full code audit that fixed 21 defects (6 critical + 12 medium + 3 low), and unified all glass dialog animations into a single manager for a more consistent animation experience. MSBuild compiles with zero errors and zero warnings — ready to use out of the box.

This update revolves around three directions: **more powerful execution flow**, **more reliable rollback closure**, and **a more unified animation experience**.

***

## 2. A More Powerful Repair Execution Window

### Step Timeline + Log Dual-Pane Layout

V1.6.30.1 upgrades the execution interface to a left-right dual-pane layout: the left pane shows the progress stage of each repair step in real time (Starting / Executing / RolledBack / Completed / Skipped), while the right pane echoes the command log simultaneously. You can watch the progress and check the specific command output side by side, without shifting your gaze back and forth.

### "Continue" or "Abort" on Failure

Previously, the only option on failure was "Abort." V1.6.30.1 adds a "Continue" option — when you choose to continue, the rollback command of the failed step is executed first, then the step is skipped and subsequent steps proceed, avoiding cascading failures caused by dirty state. The choice is now back in your hands.

### Smart Remaining-Time Estimation

The execution window estimates "how much longer" in real time based on the average duration of commands already executed. No need to stare at the progress bar — one glance tells you everything.

### Thorough Subprocess Termination on Cancel

Canceling a repair previously could leave "orphan processes" still running in the background. V1.6.30.1 switches to a process-tree-level termination mechanism — when canceled, all spawned subprocesses are killed together, leaving nothing behind.

### Pre-Check Filtering

Before execution, each command undergoes a precondition check, automatically skipping commands that don't apply to the current environment. Every step you see is one that will actually run — no more "ran but did nothing" placeholders.

***

## 3. More Reliable Undo and Rollback

### Retryable Undo on Failure

Previously, the undo button would become permanently disabled after a failure, leaving the user stuck. V1.6.30.1 keeps the retryable state — after an undo failure, you can simply click retry without restarting the program or giving up on the repair.

### Automatic Orphan Snapshot Cleanup

After an unexpected process exit, "ownerless" backup snapshots may linger on disk. V1.6.30.1 automatically cleans up snapshots older than 7 days at startup, preventing the disk from being filled with meaningless old snapshots.

### Undo Viewer Shows Disk Snapshots

Even if the session information has been lost, backup snapshots remaining on disk will appear in the undo viewer as "orphan snapshots." You can see them and manage them — no more "invisible but occupying space" situations.

### Immediate UI Refresh After Successful Undo

Fixed the issue where the UI state would not update after a successful undo — now the moment an undo completes, the relevant interface syncs to the latest state immediately, with no manual refresh or window restart needed.

***

## 4. More Stable View Switching

### 6-View Exit Timer Leak Fix

Fixed the issue where exit timers accumulated and leaked resources during rapid view switching. All 6 views (Pro mode, Smart mode, History mode, Solution Detail, Permission dialog, Session Restore) have been fixed — long sessions of frequent switching no longer cause lag.

### Proper Console Log Subscription Management

Fixed the potential risk of console logs not echoing after returning from Pro or Smart mode. Subscriptions are now properly created and released — after switching modes back and forth, the console always outputs normally.

### Entrance Animation Timers Cleared on View Unload

When a view is unloaded, its corresponding entrance animation timers are cleaned up together, preventing state anomalies caused by timers firing after unload. This is why switching feels "more responsive."

***

## 5. Stricter Final-State Protection

### Repaired Sessions Will Not Be Incorrectly Overwritten

A successfully undone session will no longer be incorrectly overwritten by a delayed completion callback into another state. A final state is a final state — once confirmed, it is locked and cannot be disrupted by asynchronous timing.

### Empty Plans Correctly Show "Partial Success"

When all commands are filtered out by pre-check and none actually execute, the status now shows as "Partial Success" instead of "Success." The semantics are more accurate, preventing the illusion that "everything has been fixed."

### Continue Mode Executes Rollback Commands

When choosing to "Continue" execution, the rollback commands corresponding to the failed command are correctly executed. No more "skipped but not rolled back" dirty-state residue, ensuring subsequent commands run in a clean environment.

***

## 6. More Unified Glass Dialog Animations

### 10 Dialog Animations Unified

Previously, 10 dialogs each implemented the same entrance/exit animation code, scattered across different files. V1.6.30.1 unifies these duplicate implementations into the `GlassDialogAnimation` utility class — defined once, reused everywhere.

### Centralized Animation Parameter Tuning

From now on, any animation duration adjustment only needs to be made in one place — no more "changed 9, missed 1" synchronization issues. Maintenance is easier, and the experience is more consistent.

### Unified Window-Level Exit Animations

The exit animations of the Performance Diagnostics dialog and Performance Upgrade dialog have also been brought under unified management. No matter which level a dialog is attached to, the animation behavior is completely consistent.

***

## 7. Smarter History Analysis and Report Export

### One Smart Analyze Button

The history view used to have two separate bottom buttons — "Trend" and "Timeline" — and you had to know which one fit your selection. V1.6.30.1 merges them into a single "Analyze" button that thinks for you. Select nothing and it shows "Analyze" with a magnifier icon (disabled, waiting for input). Select one archive and it becomes "Timeline" with a clock icon, showing that archive's internal event distribution. Select two or more and it switches to "Trend" with a rising line-chart icon, revealing the cross-archive health evolution. One button, three modes — it always knows what you need.

### Reliable Multi-Select Refresh

Previously, when you batch-selected or batch-deselected archives, the Analyze button's text and icon could get stuck on the old state because the notification was suppressed during the batch operation. V1.6.30.1 adds a post-batch notification handshake — the moment a batch selection completes, the button text (Timeline/Trend), the icon (clock/line chart), and the batch-delete label all refresh immediately. No more "selected three but the button still says Timeline."

### Accurate Cross-Archive Trends

The trend chart used to quietly pull data from the full archive list instead of just the ones you selected, so "comparing these three archives" actually showed your entire history. V1.6.30.1 corrects the data source to use only the selected archives. What you see is what you selected — cross-archive comparison is finally meaningful.

### Correct Report Format Selection

In the report export dialog, the three format radio buttons lived in different layout containers, so WPF's default mutual-exclusion rule didn't apply — you could light up all three at once. V1.6.30.1 groups them under a shared `ReportFormatGroup` name so they exclude each other properly across containers, no matter where they sit in the layout. Picking one now correctly deselects the others.

### Consistent Bilingual Reports

The report dialog used to read the global language setting, which could drift out of sync with the history view's own language choice — leaving you with an English main interface but a Chinese export dialog. V1.6.30.1 threads the language preference through a single chain: the history view passes its language to the report dialog, which passes it to the report generator and the HTML/Excel exporters. Whatever language you're working in is the language your report is in — end to end.

### Smooth Format Card Hover Feedback

The three format option cards used to have no hover feedback at all, and each selection change built a brand-new brush from scratch — abrupt transitions and needless memory churn. V1.6.30.1 gives each card a smooth 200ms color fade on hover and on selection, using reusable named brushes that animate only their `Color` property. The hover feel now matches the history list's polished feedback, and the GC pressure from per-allocation brushes is gone.

## 8. More Comprehensive Code Audit

### All 6 Critical Defects (P0) Fixed

Covering Unloaded deadlock, non-retryable undo, CTS leak, undisposed exit handle, exit without fallback, and uncleared entrance timers. These are core defects that would cause UI freezes, resource exhaustion, or unrecoverable states — all now fixed.

### All 12 Medium Defects (P1) Fixed

Covering final-state protection, snapshot cleanup, orphan snapshot loading, event subscription management, animation unification, and more. These defects are usually inconspicuous but erode stability over time — all addressed in this release.

### 3 Newly Discovered Low-Risk Audit Defects Fixed

Including empty-plan semantic contradiction, final-state branch data inconsistency, and post-undo UI not refreshing. Although low-risk, they were handled as well in pursuit of a complete closure.

### MSBuild Compiles with Zero Errors and Zero Warnings

All changes pass MSBuild compilation verification, with zero errors and zero warnings — clean and crisp.
