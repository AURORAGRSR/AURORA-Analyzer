# AURORA-Analyzer V1.5.28.5 Release Notes

***

## 1. Welcome to V1.5.28.5

Thank you for choosing AURORA-Analyzer! V1.5.28.5 is an upgrade release featuring a comprehensive rendering mechanism refactor and a brand-new console mode usability experience. We have implemented a six-in-one GPU utilization optimization for the graphics rendering pipeline, ensuring smooth and responsive interfaces across different hardware environments; built GUI/CLI dual-mode compatibility for the console mode, enabling complete smart repair flows in a pure console environment; and patched multiple animation, detection, and security defects.

***

## 2. A More Fluid Graphical Interface

### Comprehensive Rendering Mechanism Refactor

V1.5.28.5 comprehensively refactors the graphics rendering pipeline. We have introduced a six-in-one optimization mechanism: startup hardware probing, dynamic performance tiering, render layer lazy subscription, backend three-level fallback, frequency adaptive throttling, and remote session dual-path detection. Whether your device has a high-end GPU, a mainstream graphics card, or operates in a remote session or software rendering environment, AURORA-Analyzer automatically selects the most suitable rendering strategy.

### Refresh Rate Adaptive Normalization

We discovered that previous animations appeared approximately 33% faster than design intent — the root cause was that the animation normalization benchmark used the 60fps theoretical value (16.667ms), but DispatcherTimer at Render priority experiences queue scheduling jitter, yielding an actual average frame rate of only about 45fps. V1.5.28.5 corrects the normalization benchmark to 22.222ms (45fps), making the hover, breathing, and loading animation speeds of buttons, progress bars, and task HUDs perfectly consistent with design intent, delivering a more refined and responsive feel.

***

## 3. A Brand-New Console Mode Experience

### GUI/CLI Dual-Mode Compatibility

V1.5.28.5 builds the AURORA-SmartEngine-CLI.ps1 adaptation layer, enabling the smart engine to complete the full flow in a pure console environment. It adopts a three-layer architecture: thread-safe syncHash for cross-Runspace communication, background Runspace executing SmartEngine, and main thread polling responding to all GUI events. The smart engine's five wait points — elevation, authorization, CSV export confirmation, elevation remediation, and main menu loop — are all handled by console input.

### SMART SLI Smart Mode Invocation

Console mode gains SMART SLI, enabling it to invoke Smart Mode. Console users can now enjoy the automated repair capabilities of Smart Mode without switching to the GUI, completing smart diagnostics and repair directly in the console.

### Brand-New Usability Design

Console mode's overall usability has been completely redesigned: clearer menu interactions, more timely status feedback, and more robust error handling. Fixed issues including execution results not printing, manual refresh required after privilege cancellation, and duplicate menu printing, making the pure console experience as smooth as the GUI.

***

## 4. More Precise Animations and Detection

### PRO Mode Entrance Animation Fix

Fixed an issue where trailing controls in PRO mode's entrance animation would suddenly accelerate. The root cause was a fixed 1500ms fallback timer triggering too early after the control count grew to 16. We changed the fallback timer to dynamic calculation — precisely computing the fallback timing based on control count, stagger delay, and animation duration, ensuring every control plays its entrance animation completely.

### History View Hit Detection Fix

Fixed two issues in history view hit detection: health score calculation returning zero deductions due to integer division truncation, and freshly exported logs failing to match due to a fixed 24h scan window. Health score now uses floating-point arithmetic with Math.Round, and the scan window dynamically expands (taking the maximum of the default 24h and the date range span, capped at 30 days).

### Solution Entry Point Addition

After history view detection, regardless of hit or miss, as long as detection succeeds, an entry to solution details is provided. When hit with solutions, it lists solutions and guides repair; when hit without solutions, it allows viewing comparison details; when missed, it allows viewing comparison to check if the historical issue still exists.

### Bottom Buttons Staggered Entrance

Bottom buttons in the history view and solution view now fade in and slide up at a 120ms rhythm, each button first overshooting to 1.07x then converging to 1.0x with jelly elasticity, forming a coherent and rhythmic entrance sequence, replacing the previous abrupt simultaneous appearance.

***

## 5. Undo Manager Optimization

The Undo Manager (UndoViewer) has been migrated from the solution view to the smart mode view, bringing it closer to the actual repair execution scenario. Smart mode and PRO mode now both completely record every repair command to RepairService, allowing the Undo Manager to display commands executed in all modes — regardless of which mode you execute repairs in, you can view and roll them back uniformly in the Undo Manager.

***

## 6. Detail Optimizations

### Language Order

The main window view 1's language list order has been adjusted, placing "简体中文" first and "English" second, aligning with usage habits.

### Splash and Status Text

Optimized the splash screen's text layout, making the title, subtitle, and status text more visually balanced. Optimized UWP-style status text synchronization and display, ensuring status updates correctly with engine progress.

### Modal Dialog Masks

Optimized mask animations and visual effects for all modal dialogs — unified mask opacity and color tone, more coordinated wind-up — scale-up — fade rhythm for entrance/exit, unified glass container corner radius and highlight strokes, and eliminated content jumps.

***

## 7. Security Hardening

V1.5.28.5 patches multiple critical security vulnerabilities:

- **Privilege escalation command line parameter injection**: Added language whitelist validation and path metacharacter validation, preventing command line injection
- **Invoke-Expression command injection**: Replaced Invoke-Expression with safe ScriptBlock execution, added command blacklist validation and audit logging
- **Integrity check cache poisoning**: Eliminated TOCTOU window, recomputing hashes on every check
- **Encoding fix**: Added UTF-8 BOM to multiple scripts, fixing parsing issues on Chinese Windows
