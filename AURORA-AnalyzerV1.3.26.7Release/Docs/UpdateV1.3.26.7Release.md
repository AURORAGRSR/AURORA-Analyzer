## 1. 版本概述

V1.3.26.7 版本是在 V1.3.26.6 基础上的一次全面质量提升版本。在 V1.3.26.6 中，项目完成了错误处理约定、资源生命周期管理和结构化可观测性等基础架构的打磨。V1.3.26.7 则聚焦于消除代码中存在的严重功能性缺陷、安全漏洞和逻辑错误，对全部核心模块进行了深度审查和修复。

本次更新共修复了 53 个问题，涵盖 18 项严重级别（Critical）问题和 35 项高级别（High）问题。修复范围覆盖完整性监控系统、注册表还原、CleanSystem 修复、PRO 引擎参数传递、函数签名冲突、CSV 日志列错位、原子写入可靠性、自定义修复代码注入等核心功能。这些修复显著提升了系统的功能正确性、安全性和稳定性。

此外，本次更新还对代码结构进行了多项改进，包括将多个 View 对话框和控件拆分为独立文件以提升可维护性，消除了多处函数重复定义，修复了多处变量未初始化导致的运行时异常。V1.3.26.7 是一次以修复为核心的质量版本，推荐所有用户升级。

## 2. 关键功能性修复

### 完整性监控系统修复

在之前的版本中，文件完整性监控功能实际上完全失效了。原因是 .NET 的 `FileSystemWatcher.Filter` 属性不支持使用逗号分隔多个文件扩展名模式，而原代码将过滤器设置为 `"*.ps1,*.json,*.xml,*.ico,*.exe,*.enc"`，导致没有任何文件能匹配该过滤器，完整性监控从未检测到任何文件变更。在 V1.3.26.7 中，监控策略从基于 FileSystemWatcher 的直接事件订阅改为定时器轮询 + 未授权文件扫描的方式，这种方式更加稳定可靠，避免了 PowerShell 脚本块在 IOCP 线程上运行时的 Runspace 缺失问题。同时增加了 64KB 内部缓冲区、防自触发标志和并发锁保护，防止高频率文件操作导致的事件风暴和并发完整性检查。

### 注册表还原功能修复

V1.3.26.6 及之前版本中，注册表撤销操作存在一个严重的空引用异常缺陷。在调用 `reg.exe import` 执行注册表还原时，`Start-Process` 命令缺少 `-PassThru` 参数，导致返回的进程对象始终为空。后续代码尝试访问 `$process.ExitCode` 来判断还原是否成功时，必然触发空引用异常。这意味着注册表还原功能从未正常工作过。修复后的代码添加了 `-PassThru` 参数，使得进程对象正确返回，退出码能够被正确获取，注册表还原功能现在可以正常工作。

### CleanSystem 修复功能恢复

CleanSystem 修复类型在之前版本中完全失效，原因是代码使用了 `Remove-Force` 这个不存在的 PowerShell 命令。PowerShell 中正确的文件删除命令是 `Remove-Item -Force`。修复后的代码采用先删除目录再删除文件的两步方式，避免了管道重复删除导致的"目录非空"错误，系统清理功能现在可以正确清理 TEMP 目录中的临时文件。

### 自定义修复代码注入漏洞修复

自定义修复模式之前直接使用 `Invoke-Expression` 执行用户指定的命令字符串，这是一个严重的代码注入漏洞。攻击者可以通过传入恶意构造的 Target 参数执行任意 PowerShell 代码。V1.3.26.7 用一个命令白名单映射表替代了动态执行机制，目前支持清空事件日志、重置网络栈、刷新 DNS 缓存、修复系统文件、清理临时文件和重置 Windows Store 等六个安全命令。白名单外的命令会被拒绝执行，并显示支持的命令列表。这从根本上消除了代码注入风险。

## 3. 安全与完整性增强

### 完整性哈希列表中增加 SecurityModule 自身

原代码的完整性检查机制存在一个逻辑漏洞——被检查的文件列表中没有包含执行检查逻辑的安全模块本身。这意味着攻击者可以修改安全模块的代码而不被检测到。V1.3.26.7 引入了一种两阶段安全架构，通过 CHK.ENC 文件将安全模块的哈希值存储在加密签名文件中。EXE 守卫启动时首先读取并验证 CHK.ENC 中的签名和哈希值，再对 SecurityModule.ps1 进行完整性检查，确保整个安全检查链的可靠性。

### 备份快照 ID 正确传递

修复会话完成时，之前版本没有将备份快照 ID 传递给 `Complete-RepairSession` 函数。如果修复前创建了系统快照，快照 ID 会丢失，导致后续的撤销功能无法关联到正确的备份。修复后的代码正确传递了 `$session.BackupSnapshotId`，确保快照关联信息在整个修复流程中不会丢失。

### IO 异常安全失败

完整性检查在遇到 IO 异常（如文件被锁定、磁盘错误等）时，原代码会回退到上一次检查的缓存结果。这意味着攻击者可以通过制造 IO 错误来绕过完整性验证——只要上一次的检查结果是"正常"，即使文件已经被篡改，检查也会通过。V1.3.26.7 将 IO 异常场景改为安全失败模式，即不确定时直接判定为验证失败并触发安全告警，不再依赖过时的缓存结果。

### 看门狗清理纳入异常退出路径

之前的版本中，如果程序因完整性检查失败、调试器检测等安全事件而通过 `Invoke-SafeExit` 紧急退出，看门狗定时器、文件监控器、Runspace、PowerShell 实例和 WMI 事件订阅等资源的清理代码会被跳过。这些残留资源可能导致资源泄漏和进程无法正常退出。V1.3.26.7 在 `Invoke-SafeExit` 函数中增加了完整的资源清理逻辑，确保无论程序以何种方式退出，所有资源都能被正确释放。同时，LauncherGUI 中的退出清理链也进行了全面增强，包括环境变量清理、Runspace 清理、PowerShell 实例清理、管道清理和 WMI 事件订阅清理。

## 4. 架构与代码质量改进

### 函数签名冲突修复

PRO 引擎中有两个函数（`New-StreamWriterOperation` 和 `Get-SafeFilePath`）与 CoreEngine 中的同名函数签名完全不同，但它们在同一个脚本作用域中加载，后加载的版本会完全覆盖前一个。这导致调用 CoreEngine 版本的代码实际执行的是 PRO 版本，传入错误的参数类型会引发运行时异常。V1.3.26.7 将 PRO 引擎的这两个函数重命名为 `New-PROStreamWriterOperation` 和 `Get-PROSafeFilePath`，同时更新了 PRO 引擎内部的全部 11 处调用点。修复后，CoreEngine 的原始函数版本恢复，外部调用者不再受到影响。

### `return if (...)` 语法修复

在两个还原管理函数中，原代码使用了 `return if (...) { 值A } else { 值B }` 的语法，这在 PowerShell 中是非法语法——`return` 关键字后面必须跟表达式或语句块。这导致两个函数始终返回 null，还原点类型和错误信息永远显示为空白。修复后改为标准的 `if (...) { return 值A } else { return 值B }` 写法，函数现在能正确返回值。

### CSV 日志列错位修复

结构化日志系统的 CSV 导出存在列错位问题。原代码中 `Data` 列是条件性的——只有当 `$Data` 参数存在时才添加到日志条目中。`Export-Csv -Append` 命令会按照文件已有的列头写入数据，如果第一次写入没有 Data 列，后续带 Data 的写入就会将数据写入错误的列。V1.3.26.7 将 Data 列改为始终存在（无数据时写入空字符串），确保列结构从首次写入就固定，后续追加的数据不会出现错位。

### 原子写入可靠性修复

会话保存的"原子写入"实现存在数据丢失风险。原代码先删除目标文件再移动临时文件，在删除与移动之间如果进程崩溃，文件将永久丢失。此外，原修复方案使用了 `File.Move` 来实现覆盖，但在 .NET Framework 4.x 中，`File.Move` 在目标文件存在时会抛出 `IOException`，并不会自动覆盖。V1.3.26.7 改用 `[System.IO.File]::Replace()` 方法实现真正的原子替换。该方法在同一个卷上是原子操作，会保留目标文件的元数据。同时添加了 `FileNotFoundException` 兜底处理（首次写入时目标不存在的情况）和带有备份后缀的重试机制，确保会话数据在任何情况下都不会丢失或损坏。

### 多处变量未初始化修复

修复了多处因变量未定义导致的运行时异常。包括：`$techData` 在缓存命中路径中被访问但从未定义，导致知识图谱缓存永远失效——现已改为直接从 `version.txt` 读取版本号进行比较；`$lightEvents` 在严格模式下未初始化导致报错——现已添加 `@()` 初始化；`$dragAction` 在鼠标事件绑定之前未定义导致拖动窗口功能异常——已将定义提前到使用之前。

### 管理员检查参数传递修复

`Test-AdminRequired` 函数定义需要 `$LogType` 参数，但在调用处没有传递任何参数，导致管理员权限检查崩溃。V1.3.26.7 修正了调用处的参数传递。同时，`Log-RepairCommand` 函数的参数名也存在不匹配——调用方使用 `-CommandType` 而函数定义接受 `-Command`——现已修正为正确的参数名，修复操作日志现在能够正确记录。

## 5. UI 体验改进

### Write-SmartLog 日志输出恢复

SmartEngine 中有 10 处调用 `Write-SmartLog` 时传入了 `-ForegroundColor` 参数，但该函数只接受 `$Message` 和 `$Status` 两个参数。多余的参数导致 PowerShell 抛出 `ParameterBindingException` 异常，使得日志完全不输出。修复后移除了所有多余的 `-ForegroundColor` 参数，SmartEngine 的日志输出现在可以正常显示在 GUI 的日志区域中。这是一个纯收益的修复——用户在 V1.3.26.6 中看到的空白日志输出，在 V1.3.26.7 中将恢复正常。

### 函数重复定义消除

`Start-UwpExitAnimation` 函数在 AURORA-Animations.ps1 中被定义了两次，后加载的定义会覆盖前者，导致行为不可预测。V1.3.26.7 移除了第一处重复定义，确保每个函数只有一处实现，消除了行为不确定性。

### 提权对话框拖动功能修复

提权/恢复对话框的拖动窗口功能由于 `$dragAction` 变量定义在使用之后而失效。修复后将拖动操作的定义提前到控件绑定之前，对话框现在可以正常拖动。

### `#requires -RunAsAdministrator` 移除

RestoreManager.ps1 中的 `#requires -RunAsAdministrator` 指令会在非管理员环境下直接终止脚本加载，用户看不到任何友好的错误提示。V1.3.26.7 移除了该指令，改为在调用方（RepairLogger.ps1）进行运行时管理员检查，并在加载失败时显示友好的警告信息。这样用户在非管理员环境下启动时，能够看到清晰的权限不足提示而不是直接崩溃。

## 6. PRO 模式改进

### PRO 引擎参数传递修复

在 V1.3.26.6 中，PRO 入口点（AnalyzerPRO.ps1）在通过 dot-source 加载 PRO 引擎时，所有命令行参数（Language、LogType、EventId、StartTime、EndTime 等）都没有被传递到引擎内部，导致引擎始终使用默认值运行。这意味着用户通过 GUI 选择的语言、日志类型、时间范围等设置全部被忽略。V1.3.26.7 在入口点文件中设置了 `$script:PRO_*` 系列脚本级变量，PRO 引擎在加载时从这些变量中读取参数，并保留了合理的默认值作为回退。同时，PRO 引擎内部的启动守卫检查和语言变量赋值也已同步更新。

### 健康等级文字本地化

PRO 模式的健康评估功能中，"优秀"、"良好"、"一般"、"较差"等等级文字以及对应的状态描述全部硬编码为中文。在英文模式下，用户仍然看到中文的健康等级文字，本地化完全失效。V1.3.26.7 在语言资源文件（Language.psd1）中添加了健康等级的中英文键值对，PRO 引擎中的硬编码字符串全部替换为从 `$script:Loc` 获取。切换中英文后，健康等级文字现在能正确跟随语言设置。

### CoreEngine 提前导入

PRO 入口点中，启动检测代码调用了 `Invoke-SafeExit` 函数，但定义该函数的 CoreEngine 在检测代码之后才导入。如果启动检测触发（如非法直接运行），程序会抛出"命令未找到"异常而不是显示友好的错误提示。V1.3.26.7 将 CoreEngine 的导入移到了启动检测之前，确保所有必要的函数在检测执行前已可用。

### SecurityModule 提前导入

PRO 入口点的 RSA 令牌验证调用了 `Test-RSATokenSignature` 函数，但定义该函数的 SecurityModule 从未被导入。V1.3.26.7 在启动检测之前导入了 SecurityModule，确保 RSA 令牌验证功能正常工作。

## 7. 构建系统改进

### CRC32 自校验嵌入修复

构建脚本中 CRC32 自校验值的嵌入逻辑存在一个缺陷：用于替换的占位符字符串可能不存在于 C# 模板中，导致替换操作不执行任何操作，EXE 中永远嵌入默认的 `0x00000000` 值，CRC 自校验特性完全失效。V1.3.26.7 修正了 CRC32 算法实现，使用标准的多项式 `0xEDB88320` 进行计算，并确认了占位符的存在性。

### LauncherGUI 纳入完整性监控

之前版本的完整性哈希列表中缺少主启动器文件（AURORA-AnalyzerLauncherGUI.ps1），这意味着启动器被修改不会被 C# 完整性守卫检测到。V1.3.26.7 已将 LauncherGUI 添加到构建脚本的守卫目标文件列表中，确保整个程序链的完整性都能被监控。

### 代码结构优化

V1.3.26.7 对代码结构进行了多项优化。将多个 View 对话框（提权对话框、权限信息对话框、会话恢复对话框等）和 UI 控件从主启动器文件中拆分为独立模块文件，提升了代码的可维护性和可读性。这些拆分不影响任何功能行为，只是改善了代码组织方式。
