## 1. 版本概述

V1.5.29.0 是 AURORA-Analyzer 在 V1.5.28.5 渲染机制重构与控制台模式升级基础上的"视觉沉浸感与交互一致性"专项打磨版本。本次更新将 V1.5.28.6 ~ V1.5.28.29 期间陆续落地的多处动效、视差、对话框、语言切换与导航防抖修复统一打包发布，围绕七大核心领域展开：

1. **星场视差多层深度重塑**：将原 4 级深度方案扩展为 7 级深度映射（Level 0 ~ Level 6，0.00 ~ 1.00），不增加渲染星星数，仅控制全局视差强度，让每一次视图切换都能看到可见的"前进穿梭 / 后退归位"动效，彻底消除原方案中三个"无视差"分支
2. **对话框视觉统一与 Overlay 架构移除**：5 个对话框窗口根 `UserControl` 移除 `Background` 属性（默认 null，空白区域不参与命中测试，鼠标事件穿透到壳星场），让全局星空贯穿对话框，与 ProModeView / SmartModeView / MainFormView 视觉一致；同时移除 IAuroraOverlay 接口、PushOverlay/PopOverlay/RemoveOverlay 方法与 OverlayLayer Grid 全套 Overlay 基础设施
3. **权限选择时序前置**：将权限选择（ElevationDialog）从主窗口内部前置到 Splash 启动画面之后、主窗口之前，让权限流程与主流程解耦
4. **UWP 文本过渡曲线与语言切换修复**：主窗口右侧说明文本采用 UWP 标准退出曲线（0.7,0,0.3,1）与入场曲线（0.1,0.9,0.2,1），并对语言切换通知顺序重排，根除切换语言时文本仍显示旧语言缓存的缺陷
5. **智能模式状态文本位置修复**：智能模式 UWP 状态文本位置计算加入重试机制（最多 25 次、80ms 间隔，覆盖 1000ms 壳入场动画）、X 上界检查与布局完成检查，防止文本被挤压到右下角飞出
6. **键盘焦点与导航防抖统一**：主窗口右侧说明文本的鼠标悬停与键盘焦点共用 focusHandler；用 ViewManager.IsNavigating 统一导航锁替代 ProModeView 本地 `_isSwitching` 标志，并补全 5 个导航入口的防重入检查，根除快速切换时的闪回
7. **星场视差性能优化**：视差期间跳过 SoftGlow 与 DiffractionSpike（其开销与星星数线性相关，导致严重掉帧），改为在 DrawAurora 极光层引入 +50% alpha 增强作为视觉反馈（固定开销，与星星数无关），并用 smoothstep 平滑过渡避免亮度跳变

在视差深度方面，V1.5.29.0 建立了完整的 7 级深度映射链路：

| 深度级别 | 深度值 | 视图 | 视觉语义 |
|----------|--------|------|----------|
| Level 0 | 0.00 | SplashScreenView | 最深处，启动画面 |
| Level 1 | 0.15 | MainFormView view1（LanguageSelection） | 主窗体入口 |
| Level 2 | 0.30 | MainFormView view2（ModeSelection） | 主窗体模式选择 |
| Level 3 | 0.50 | ProModeView | 专业模式 |
| Level 4 | 0.60 | SmartModeView | 智能模式 |
| Level 5 | 0.85 | Elevation/SessionRestore/ExportHistory/UndoViewer | 对话框近景 |
| Level 6 | 1.00 | SolutionDetailView | 最浅处，详情页 |

MainFormView 的深度由其内部 `CurrentInternalDepth` 属性动态决定（view1=0.15、view2=0.30），使跨视图切换返回 MainForm 时星场能落在正确的内部视图层级。

在性能优化方面，V1.5.29.0 用"极光层 +50%"替代"近景星辉光"作为视差视觉反馈：

| 反馈机制 | 开销特性 | 性能表现 | 视觉效果 |
|----------|----------|----------|----------|
| SoftGlow + DiffractionSpike（原方案） | 与星星数线性相关 | 严重掉帧 | 单星辉光明显 |
| DrawAurora alpha +50%（新方案） | 固定开销，与星星数无关 | 流畅 | 极光层整体增强 |

在导航防抖方面，V1.5.29.0 用 `ViewManager.IsNavigating` 公共属性建立统一导航锁，替代各视图私有的 `_isSwitching` 标志，确保退场动画播放期间任何新导航请求都被拒绝。

本次更新是一个"视差深度全面重塑、对话框视觉统一、权限流程解耦、UWP 动效精准匹配、交互防抖统一"的版本。所有面向用户的命令行参数、环境变量接口、syncHash 同步机制与材质管线接口均保持完全兼容，确保现有脚本和工作流无需修改即可运行。

## 2. 星场视差多层深度重塑

V1.5.29.0 对星场视差进行了多层深度重塑，建立 7 级深度映射，不增加渲染星星数，仅控制全局视差强度（`_viewParallaxPhase`）。

### 2.1 问题背景

原 4 级深度方案存在三个"无视差"分支：

- **Splash → MainForm**：两者同处 0.0 深度，切换时星场无可见视差
- **ProMode ↔ SmartMode**：两者同处 0.35 深度，切换时星场无可见视差
- **MainForm 内部 view1 ↔ view2**：0.0 ↔ 0.1 差值过小，视差几乎不可见

### 2.2 7 级深度映射

`ViewManager.GetViewDepth` 按视图类型返回深度值：

```
SplashScreenView        → 0.00
MainFormView            → CurrentInternalDepth（view1=0.15 / view2=0.30）
ProModeView             → 0.50
SmartModeView           → 0.60
ExportHistoryView       → 0.85
UndoViewerView          → 0.85
ElevationDialogView     → 0.85
SessionRestoreDialogView→ 0.85
SolutionDetailView      → 1.00
```

### 2.3 MainForm 内部动态深度

`MainFormView.CurrentInternalDepth` 属性根据 `_viewModel.CurrentState` 动态返回：

```csharp
public double CurrentInternalDepth
{
    get
    {
        if (_viewModel == null) return 0.15;
        return _viewModel.CurrentState == MainFormViewState.ModeSelection ? 0.30 : 0.15;
    }
}
```

使跨视图切换返回 MainForm 时星场能落在正确的内部视图层级。

### 2.4 视差强度系数增强

`AuroraStarfield.cs` 调整两个视差强度系数，让深度差异在视觉上更明显：

| 系数 | 原值 | 新值 | 作用 |
|------|------|------|------|
| 径向位移系数 | 0.18 | 0.28 | `pushAmount = parallaxSmooth * depth * 0.28`，控制星星径向位移幅度 |
| 透明度衰减系数 | 0.5 | 0.62 | `starOpacityMul = 1.0 - parallaxSmooth * depth * 0.62`，控制星星透明度衰减 |

### 2.5 视差时长动态对齐

`StartParallaxCycle` 接收 `targetPhase` 参数，从 `_parallaxStartPhase` 平滑插值到 `_parallaxTargetPhase`。视差总时长由 `ViewManager` 根据目标视图的退场 + 入场动画实际总时长动态计算，确保视差与视图切换动画完全同步。

### 2.6 影响范围

`ViewManager.cs` GetViewDepth、`MainFormView.xaml.cs` CurrentInternalDepth、`AuroraStarfield.cs` StartParallaxCycle 及视差绘制路径。

## 3. 对话框视觉统一与 Overlay 架构移除

V1.5.29.0 对 5 个对话框窗口进行了视觉统一重构，并移除整套 Overlay 基础设施。

### 3.1 对话框背景透明化

5 个对话框窗口根 `UserControl` 移除 `Background` 属性（默认 null）：

| 对话框 | 原背景 | 新背景 |
|--------|--------|--------|
| ElevationDialogView | 不透明/半透明色 | null（默认） |
| SessionRestoreDialogView | 不透明/半透明色 | null（默认） |
| UndoViewerView | 不透明/半透明色 | null（默认） |
| ExportHistoryView | 不透明/半透明色 | null（默认） |
| SolutionDetailView | 不透明/半透明色 | null（默认） |

默认 null 背景比 `Transparent` 更彻底：不仅视觉透明，还不参与命中测试，鼠标事件直接穿透到壳星场。这让全局星空能贯穿对话框，与 ProModeView / SmartModeView / MainFormView 视觉风格完全一致。

### 3.2 Overlay 基础设施移除

移除全套 Overlay 基础设施：

- **IAuroraOverlay 接口**：完全删除
- **PushOverlay / PopOverlay / RemoveOverlay 方法**：从 ViewManager.cs 完全删除
- **OverlayLayer Grid**：从 MainWindow.xaml 完全删除

MainWindow.xaml 现仅保留两个子元素：

```xml
<Grid x:Name="RootGrid">
    <ctrl:AuroraStarfield x:Name="StarfieldBg" />
    <ContentControl x:Name="MainContent" Panel.ZIndex="1" />
</Grid>
```

仅保留 `IAuroraStaggerView` 接口用于错峰入场动效。

### 3.3 影响范围

`MainWindow.xaml`、`ViewManager.cs`、5 个对话框 `.xaml` 与 `.cs` 文件。

## 4. 权限选择时序前置

V1.5.29.0 将权限选择（ElevationDialog）从主窗口内部前置到 Splash 启动画面之后、主窗口之前。

### 4.1 新启动流程

```
App 启动
  → MainWindow 壳创建
  → NavigateTo<SplashScreenView>
  → SplashScreen LoadingComplete
  → 检测 IsCurrentProcessElevated
     ├─ 已提权 → NavigateToMainForm
     └─ 未提权 → ShowElevationDialogDirectly
                   → ElevationDialogView（深度 0.85）
                   → OnElevationResult
                      ├─ Elevate → RestartAsAdmin / 回退 MainForm
                      ├─ ContinueNormal → NavigateToMainFormFromElevation
                      └─ Exit
```

### 4.2 关键方法

- `SplashScreenView.ShowMainWindow`：根据 `ElevationService.IsCurrentProcessElevated()` 分流
- `SplashScreenView.ShowElevationDialogDirectly`：从 Splash 直接导航到 ElevationDialogView
- `SplashScreenView.OnElevationResult`：处理 Elevate / ContinueNormal / Exit 三种结果
- `SplashScreenView.NavigateToMainFormFromElevation`：用 `NavigateTo<MainFormView>(true, true)`（`replaceCurrent=true`）弹出 Elevation 并压入 MainForm，触发 0.85 → 0.15 深度视差

### 4.3 设计收益

权限流程与主流程解耦：权限选择不再占用主窗口视图槽位，主窗口专注于语言选择与模式选择；权限对话框作为独立视图参与星场视差深度链路（Level 5，0.85）。

### 4.4 影响范围

`App.xaml.cs` 启动流程、`SplashScreenView.xaml.cs` ShowMainWindow/ShowElevationDialogDirectly/OnElevationResult/NavigateToMainFormFromElevation。

## 5. UWP 文本过渡曲线与语言切换修复

V1.5.29.0 对主窗口右侧说明文本的切换动画与语言切换通知顺序进行了统一修复。

### 5.1 UWP 标准过渡曲线

`MainFormView.PlayElementSwitch` 采用 UWP 标准速度曲线：

| 曲线 | KeySpline | 用途 |
|------|-----------|------|
| exitSpline | (0.7, 0.0, 0.3, 1.0) | 退出曲线，UWP 标准减速 |
| enterSpline | (0.1, 0.9, 0.2, 1.0) | 入场曲线，UWP 标准加速 |
| settleSpline | (0.45, 0.05, 0.55, 0.95) | 收敛曲线，过冲后柔和 S 形回落 |

### 5.2 动画参数

| 参数 | 值 | 说明 |
|------|----|------|
| exitMs | 320ms | 退出时长 |
| enterMs | 640ms | 入场时长 |
| overMs | 420ms | 过冲到达 1.08 的时刻 |
| 位移 | ±52px | 退出 -52*dir，入场 +52*dir |
| 退出缩放 | 0.92 | ScaleX/ScaleY 同步 |
| 过冲 | 1.08 | ScaleX/ScaleY 同步，随后收敛到 1.0 |

### 5.3 语言切换通知顺序修复

**问题**：`MainFormViewModel.OnSelectLanguage` 原顺序为 `SelectedLanguage → IsBusy → CurrentState（触发 AnimateViewTransition）→ OnPropertyChanged`，导致 `SmartModeInfoTitle` 等绑定在切换动画播放期间仍显示旧语言缓存。

**修复**：将全部 16 个 `OnPropertyChanged(...)` 通知前置到 `CurrentState` 赋值之前：

- 5 个按钮文本：SmartButtonText、GUIButtonText、ConsoleButtonText、BackButtonText、ExitButtonText
- 2 个语言面板字段：LanguageInfoTitle、LanguageInfoDesc
- 4 个语言说明字段：ChineseInfoTitle/Desc、EnglishInfoTitle/Desc
- 4 个模式说明字段：SmartModeInfoTitle/Desc、ProModeInfoTitle/Desc、ConsoleModeInfoTitle/Desc
- 最后才执行 `IsBusy = true` 与 `CurrentState = MainFormViewState.ModeSelection`

### 5.4 缓存实例语言刷新

`ProModeView.Initialize` 与 `SmartModeView.Initialize` 新增 `language` 参数，即使在 `_initialized=true`（NavigationCache 复用）的情况下也同步刷新 `_viewModel.Language`：

```csharp
// ProModeView：在 _initialized 守卫之前刷新
if (!string.IsNullOrEmpty(language) && _viewModel != null)
{
    _viewModel.Language = language;
}
if (_initialized) return;

// SmartModeView：复用缓存实例时提前 return
if (_initialized && _viewModel != null && !string.IsNullOrEmpty(language))
{
    _viewModel.Language = language;
    return;
}
```

### 5.5 影响范围

`MainFormView.xaml.cs` PlayElementSwitch、`MainFormViewModel.cs` OnSelectLanguage、`ProModeView.xaml.cs` Initialize、`SmartModeView.xaml.cs` Initialize。

## 6. 智能模式状态文本位置修复

V1.5.29.0 修复了智能模式下 UWP 状态文本被挤压到右下角并飞出的问题。

### 6.1 问题

SmartModeView 的 UWP 状态文本（StatusText）在壳入场动画期间，因 `ProgressAnchor.ActualHeight/ActualWidth` 尚未完成布局，位置计算返回错误坐标，导致文本被定位到右下角甚至飞出可视区域。

### 6.2 修复

`SmartModeView.BeginInvokeUpdateStatusTextPositionWithRetry` 加入三层保护：

| 保护机制 | 实现 | 作用 |
|----------|------|------|
| 重试机制 | 最多 25 次，80ms 间隔 | 覆盖 1000ms 壳入场动画，等布局完成 |
| 布局完成检查 | `ActualHeight/ActualWidth <= 0` 返回 false | 避免使用未完成的坐标 |
| 自身缩放检查 | `Math.Abs(s - 1.0) > 0.01` 返回 false（V1.5.28.17） | 动画进行中不计算位置 |
| X 上界检查 | `targetX < ActualWidth` | 防止文本飞出右边缘 |

`UpdateStatusTextPosition` 在 `success == false` 时调度下一次重试定时器，直到布局完成或达到重试上限。

### 6.3 重试参数演进

| 版本 | 重试次数 | 间隔 | 覆盖时长 |
|------|----------|------|----------|
| V1.5.28.9（初版） | 5 | 50ms | 250ms（不足以覆盖 1000ms 壳动画） |
| V1.5.28.17（当前） | 25 | 80ms | 2000ms（完全覆盖 1000ms 壳动画） |

### 6.4 影响范围

`SmartModeView.xaml.cs` BeginInvokeUpdateStatusTextPositionWithRetry、UpdateStatusTextPosition。

## 7. 键盘焦点与导航防抖统一

V1.5.29.0 修复了主窗口右侧说明文本不响应键盘焦点的问题，并用统一导航锁根除快速切换闪回。

### 7.1 键盘焦点修复

**问题**：`MainFormView.AttachInfoHover` 仅绑定 `MouseEnter` 事件，键盘 Tab 焦点切换到按钮时，右侧说明文本不更新。

**修复**：提取公共悬停逻辑为 `focusHandler`，`MouseEnter` 与 `GotFocus` 共用同一处理器：

```csharp
System.EventHandler<RoutedEventArgs> focusHandler = (s, args) =>
{
    try
    {
        if (_isPanelSwitching) return;
        int currentIndex = isLangPanel ? _currentLangIndex : _currentModeInfoIndex;
        if (index == currentIndex) return;
        // ... 共用逻辑
    }
    catch (Exception ex) { /* 日志 */ }
};

btn.MouseEnter += (s, args) => focusHandler(s, args);
btn.GotFocus += (s, args) => focusHandler(s, args);
```

5 个按钮（ChineseBtn、EnglishBtn、SmartModeBtn、ProModeBtn、ConsoleModeBtn）均同时绑定两个事件。

### 7.2 统一导航锁

**问题**：ProModeView 使用本地 `_isSwitching` 标志防抖，其他视图无防抖，导致快速切换时退场动画被中断、`DiscreteDoubleKeyFrame` 起始值跳变，产生闪回。

**修复**：用 `ViewManager.IsNavigating` 公共属性（暴露内部 `_isNavigating` 字段）建立统一导航锁：

- ProModeView 移除本地 `_isSwitching` 标志，统一用 `ViewManager.IsNavigating`
- 所有导航入口在动画期间拒绝新请求

### 7.3 5 个导航入口防重入检查

| # | 文件 | 方法 | 行为 |
|---|------|------|------|
| 1 | SmartModeView.xaml.cs | OnReturnToProRequested | `if (ViewManager.Current.IsNavigating) return;` |
| 2 | SmartModeView.xaml.cs | OnShowUndoViewerRequested | `if (ViewManager.Current.IsNavigating) return;` |
| 3 | ExportHistoryView.xaml.cs | OnCloseRequested | `if (ViewManager.Current.IsNavigating) return;` |
| 4 | ExportHistoryView.xaml.cs | OpenSolutionDetail | `if (ViewManager.Current.IsNavigating) return;` |
| 5 | SolutionDetailView.xaml.cs | OnCloseRequested | `if (ViewManager.Current.IsNavigating) return;` |

此外 ProModeView 的 OnShowHistoryRequested（886 行）与另一处导航（910 行）也使用同一守卫，均标注 V1.5.28.23。

### 7.4 影响范围

`MainFormView.xaml.cs` AttachInfoHover、`ViewManager.cs` IsNavigating、`ProModeView.xaml.cs`、`SmartModeView.xaml.cs`、`ExportHistoryView.xaml.cs`、`SolutionDetailView.xaml.cs`。

## 8. 星场视差性能优化（极光层 +50%）

V1.5.29.0 修复了星场视差期间的严重掉帧问题，用极光层增强替代星辉光作为视觉反馈。

### 8.1 问题

原方案在视差期间为近景星星启用 SoftGlow（柔和辉光）与 DiffractionSpike（衍射星芒），但两者开销与星星数线性相关：

- `DrawSoftGlow` 每颗星星都要 PushTransform + DrawGeometry
- `PushTransform/DrawGeometry` 在大量星星时导致严重掉帧

### 8.2 修复方案

**跳过 SoftGlow 与 DiffractionSpike**：视差期间（`isParallaxCycling == true`）两个分支均被跳过：

```csharp
bool isParallaxCycling = (_parallaxState == ParallaxState.Cycling);

// SoftGlow 分支：视差期间跳过
if (!isParallaxCycling && star.HasSettled && ...) { ... }

// DiffractionSpike 分支：视差期间跳过
if (!isParallaxCycling && AuroraRenderEngine.CurrentTier >= PerformanceTier.Performance && ...) { ... }
```

**DrawAurora 极光层 +50% alpha 增强**：作为视觉反馈替代，开销固定，与星星数无关：

```csharp
double parallaxBoost = 1.0;
if (_parallaxState == ParallaxState.Cycling)
{
    // smoothstep 平滑过渡：ramp up 0→25%、hold 25-75%、ramp down 75-100%
    double pSmooth = ...;
    parallaxBoost = 1.0 + pSmooth * 0.5;  // 最大 1.5（+50%）
}
localAlpha *= parallaxBoost;
```

### 8.3 smoothstep 平滑过渡（V1.5.28.27）

`parallaxBoost` 使用实际动画时间进度 `t`（0→1）配合 smoothstep 计算梯形曲线：

| 阶段 | t 范围 | pSmooth | parallaxBoost |
|------|--------|---------|---------------|
| Ramp up | 0% ~ 25% | 0 → 1 | 1.0 → 1.5 |
| Hold | 25% ~ 75% | 1 | 1.5 |
| Ramp down | 75% ~ 100% | 1 → 0 | 1.5 → 1.0 |

避免视差从 Cycling 切换到 Idle 时的亮度跳变。

### 8.4 方案对比

| 反馈机制 | 开销特性 | 性能表现 | 视觉效果 |
|----------|----------|----------|----------|
| SoftGlow + DiffractionSpike（原方案） | 与星星数线性相关 | 严重掉帧 | 单星辉光明显 |
| DrawAurora alpha +50%（新方案） | 固定开销，与星星数无关 | 流畅 | 极光层整体增强 |

### 8.5 影响范围

`AuroraStarfield.cs` DrawStars（SoftGlow/DiffractionSpike 分支）、DrawAurora（parallaxBoost 计算）。

## 10. 已知限制

### 10.1 视差深度的主观感知差异

7 级深度映射的深度值（0.00 ~ 1.00）基于视觉主观感知校准。在极端高刷新率（240Hz+）显示器上，视差插值可能与设计预期略有差异，但视觉一致性优于此前。

### 10.2 极光层增强的性能边界

DrawAurora +50% alpha 增强是固定开销，但在 Eco 挡位（软件渲染或远程会话）下，极光层本身可能已被降级，增强效果可能不明显。

### 10.3 对话框背景穿透的命中测试

对话框根 `UserControl` 移除 `Background` 属性后，空白区域不参与命中测试，鼠标事件穿透到壳星场。这是刻意的视觉一致性设计，但意味着对话框空白区域的右键等事件不会被子元素拦截。

### 10.4 导航防抖的边界

`ViewManager.IsNavigating` 统一导航锁在退场动画期间拒绝所有新导航请求。如果用户在动画期间快速连续点击不同视图，只有第一个请求会执行，后续请求被静默丢弃（无错误提示）。
