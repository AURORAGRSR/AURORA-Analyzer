## 1. Version Overview

V1.5.29.0 is an AURORA-Analyzer release focused on "visual immersion and interaction consistency", building upon the V1.5.28.5 rendering mechanism refactor and console mode upgrade. This update packages the animation, parallax, dialog, language switch, and navigation anti-bounce fixes that landed incrementally across V1.5.28.6 ~ V1.5.28.29, centering on seven core areas:

1. **Starfield Parallax Multi-Level Depth Reshape**: Expands the original 4-level depth scheme into a 7-level depth mapping (Level 0 ~ Level 6, 0.00 ~ 1.00), without increasing the rendered star count — only controlling the global parallax intensity — so every view switch shows a visible "forward穿梭 / backward归位" motion, completely eliminating the three "no-parallax" branches in the original scheme
2. **Dialog Visual Unification and Overlay Architecture Removal**: The 5 dialog windows' root `UserControl` removes the `Background` attribute (defaults to null, blank areas do not participate in hit testing, mouse events pass through to the shell starfield), letting the global starfield flow through dialogs for visual consistency with ProModeView / SmartModeView / MainFormView; simultaneously removes the entire Overlay infrastructure including the IAuroraOverlay interface, PushOverlay/PopOverlay/RemoveOverlay methods, and the OverlayLayer Grid
3. **Permission Selection Timing Relocation**: Moves the permission selection (ElevationDialog) from inside the main window to after the Splash screen and before the main window, decoupling the permission flow from the main flow
4. **UWP Text Transition Curves and Language Switch Fix**: The main window's right-side explanatory text adopts the UWP standard exit curve (0.7,0,0.3,1) and entrance curve (0.1,0.9,0.2,1), and reorders the language switch notification sequence to eradicate the defect where text still showed old language cache during language switch
5. **Smart Mode Status Text Position Fix**: Smart mode UWP status text position calculation adds a retry mechanism (up to 25 times, 80ms interval, covering the 1000ms shell entrance animation), an X upper bound check, and a layout completion check, preventing the text from being squeezed to the bottom-right corner and flying out
6. **Keyboard Focus and Navigation Anti-Bounce Unification**: The main window's right-side explanatory text shares a focusHandler between mouse hover and keyboard focus; uses ViewManager.IsNavigating as the unified navigation lock to replace ProModeView's local `_isSwitching` flag, and adds anti-reentry checks at 5 navigation entry points, eradicating the flashback caused by quick switching
7. **Starfield Parallax Performance Optimization**: During parallax, skips SoftGlow and DiffractionSpike (whose cost scales linearly with star count, causing severe frame drops), and instead introduces a +50% alpha boost in the DrawAurora aurora layer as visual feedback (fixed cost, independent of star count), with smoothstep smoothing to avoid brightness discontinuity

For parallax depth, V1.5.29.0 establishes a complete 7-level depth mapping chain:

| Depth Level | Depth Value | View | Visual Semantics |
|-------------|-------------|------|------------------|
| Level 0 | 0.00 | SplashScreenView | Deepest, splash screen |
| Level 1 | 0.15 | MainFormView view1 (LanguageSelection) | Main window entry |
| Level 2 | 0.30 | MainFormView view2 (ModeSelection) | Main window mode selection |
| Level 3 | 0.50 | ProModeView | Pro mode |
| Level 4 | 0.60 | SmartModeView | Smart mode |
| Level 5 | 0.85 | Elevation/SessionRestore/ExportHistory/UndoViewer | Dialog near field |
| Level 6 | 1.00 | SolutionDetailView | Shallowest, detail page |

MainFormView's depth is dynamically determined by its internal `CurrentInternalDepth` property (view1=0.15, view2=0.30), so the starfield lands on the correct internal view level when returning to MainForm across view switches.

For performance optimization, V1.5.29.0 replaces "near-star glow" with "aurora layer +50%" as the parallax visual feedback:

| Feedback Mechanism | Cost Characteristic | Performance | Visual Effect |
|--------------------|---------------------|-------------|---------------|
| SoftGlow + DiffractionSpike (original) | Linear with star count | Severe frame drops | Per-star glow visible |
| DrawAurora alpha +50% (new) | Fixed cost, independent of star count | Fluid | Aurora layer overall boost |

For navigation anti-bounce, V1.5.29.0 establishes a unified navigation lock via the `ViewManager.IsNavigating` public property, replacing each view's private `_isSwitching` flag, ensuring any new navigation request is rejected during exit animation playback.

This update is a "comprehensive parallax depth reshape, dialog visual unification, permission flow decoupling, precise UWP animation matching, unified interaction anti-bounce" release. All user-facing command-line parameters, environment variable interfaces, the syncHash synchronization mechanism, and the material pipeline interface remain fully compatible, ensuring existing scripts and workflows run without modification.

## 2. Starfield Parallax Multi-Level Depth Reshape

V1.5.29.0 reshapes the starfield parallax into a multi-level depth system, establishing a 7-level depth mapping without increasing the rendered star count — only controlling the global parallax intensity (`_viewParallaxPhase`).

### 2.1 Background

The original 4-level depth scheme had three "no-parallax" branches:

- **Splash → MainForm**: Both at depth 0.0, no visible parallax during switch
- **ProMode ↔ SmartMode**: Both at depth 0.35, no visible parallax during switch
- **MainForm internal view1 ↔ view2**: 0.0 ↔ 0.1 difference too small, parallax barely visible

### 2.2 7-Level Depth Mapping

`ViewManager.GetViewDepth` returns depth values by view type:

```
SplashScreenView        → 0.00
MainFormView            → CurrentInternalDepth (view1=0.15 / view2=0.30)
ProModeView             → 0.50
SmartModeView           → 0.60
ExportHistoryView       → 0.85
UndoViewerView          → 0.85
ElevationDialogView     → 0.85
SessionRestoreDialogView→ 0.85
SolutionDetailView      → 1.00
```

### 2.3 MainForm Internal Dynamic Depth

The `MainFormView.CurrentInternalDepth` property dynamically returns based on `_viewModel.CurrentState`:

```csharp
public double CurrentInternalDepth
{
    get
    {
        if (_viewModel == null) return 0.15;
        return _viewModel.CurrentState == MainFormViewState.ModeSelection ? 0.30 : 0.15;
    }
}
```

So the starfield lands on the correct internal view level when returning to MainForm across view switches.

### 2.4 Parallax Intensity Coefficient Boost

`AuroraStarfield.cs` adjusts two parallax intensity coefficients to make depth differences more visually apparent:

| Coefficient | Original | New | Effect |
|-------------|----------|-----|--------|
| Radial displacement coefficient | 0.18 | 0.28 | `pushAmount = parallaxSmooth * depth * 0.28`, controls star radial displacement amplitude |
| Transparency attenuation coefficient | 0.5 | 0.62 | `starOpacityMul = 1.0 - parallaxSmooth * depth * 0.62`, controls star transparency attenuation |

### 2.5 Parallax Duration Dynamic Alignment

`StartParallaxCycle` accepts a `targetPhase` parameter, smoothly interpolating from `_parallaxStartPhase` to `_parallaxTargetPhase`. The total parallax duration is dynamically computed by `ViewManager` based on the target view's actual exit + entrance animation total duration, ensuring parallax is fully synchronized with the view switch animation.

### 2.6 Impact Scope

`ViewManager.cs` GetViewDepth, `MainFormView.xaml.cs` CurrentInternalDepth, `AuroraStarfield.cs` StartParallaxCycle and parallax rendering path.

## 3. Dialog Visual Unification and Overlay Architecture Removal

V1.5.29.0 performs visual unification refactoring on 5 dialog windows and removes the entire Overlay infrastructure.

### 3.1 Dialog Background Transparentization

The 5 dialog windows' root `UserControl` removes the `Background` attribute (defaults to null):

| Dialog | Original Background | New Background |
|--------|---------------------|----------------|
| ElevationDialogView | Opaque/translucent color | null (default) |
| SessionRestoreDialogView | Opaque/translucent color | null (default) |
| UndoViewerView | Opaque/translucent color | null (default) |
| ExportHistoryView | Opaque/translucent color | null (default) |
| SolutionDetailView | Opaque/translucent color | null (default) |

The default null background is more thorough than `Transparent`: not only visually transparent, but also does not participate in hit testing — mouse events pass through directly to the shell starfield. This lets the global starfield flow through all dialogs, fully consistent with the visual style of ProModeView / SmartModeView / MainFormView.

### 3.2 Overlay Infrastructure Removal

Removes the entire Overlay infrastructure:

- **IAuroraOverlay interface**: Completely deleted
- **PushOverlay / PopOverlay / RemoveOverlay methods**: Completely deleted from ViewManager.cs
- **OverlayLayer Grid**: Completely deleted from MainWindow.xaml

MainWindow.xaml now retains only two child elements:

```xml
<Grid x:Name="RootGrid">
    <ctrl:AuroraStarfield x:Name="StarfieldBg" />
    <ContentControl x:Name="MainContent" Panel.ZIndex="1" />
</Grid>
```

Only the `IAuroraStaggerView` interface is retained for staggered entrance animations.

### 3.3 Impact Scope

`MainWindow.xaml`, `ViewManager.cs`, 5 dialog `.xaml` and `.cs` files.

## 4. Permission Selection Timing Relocation

V1.5.29.0 relocates the permission selection (ElevationDialog) from inside the main window to after the Splash screen and before the main window.

### 4.1 New Startup Flow

```
App startup
  → MainWindow shell creation
  → NavigateTo<SplashScreenView>
  → SplashScreen LoadingComplete
  → Detect IsCurrentProcessElevated
     ├─ Elevated → NavigateToMainForm
     └─ Not elevated → ShowElevationDialogDirectly
                   → ElevationDialogView (depth 0.85)
                   → OnElevationResult
                      ├─ Elevate → RestartAsAdmin / fallback MainForm
                      ├─ ContinueNormal → NavigateToMainFormFromElevation
                      └─ Exit
```

### 4.2 Key Methods

- `SplashScreenView.ShowMainWindow`: Branches based on `ElevationService.IsCurrentProcessElevated()`
- `SplashScreenView.ShowElevationDialogDirectly`: Navigates directly from Splash to ElevationDialogView
- `SplashScreenView.OnElevationResult`: Handles Elevate / ContinueNormal / Exit results
- `SplashScreenView.NavigateToMainFormFromElevation`: Uses `NavigateTo<MainFormView>(true, true)` (`replaceCurrent=true`) to pop Elevation and push MainForm, triggering 0.85 → 0.15 depth parallax

### 4.3 Design Benefits

Decoupling permission flow from main flow: permission selection no longer occupies a main window view slot, the main window focuses on language selection and mode selection; the permission dialog participates in the starfield parallax depth chain as an independent view (Level 5, 0.85).

### 4.4 Impact Scope

`App.xaml.cs` startup flow, `SplashScreenView.xaml.cs` ShowMainWindow/ShowElevationDialogDirectly/OnElevationResult/NavigateToMainFormFromElevation.

## 5. UWP Text Transition Curves and Language Switch Fix

V1.5.29.0 performs unified fixes on the main window's right-side explanatory text switch animation and language switch notification sequence.

### 5.1 UWP Standard Transition Curves

`MainFormView.PlayElementSwitch` adopts UWP standard speed curves:

| Curve | KeySpline | Purpose |
|-------|-----------|---------|
| exitSpline | (0.7, 0.0, 0.3, 1.0) | Exit curve, UWP standard deceleration |
| enterSpline | (0.1, 0.9, 0.2, 1.0) | Entrance curve, UWP standard acceleration |
| settleSpline | (0.45, 0.05, 0.55, 0.95) | Settle curve, soft S-curve after overshoot |

### 5.2 Animation Parameters

| Parameter | Value | Description |
|-----------|-------|-------------|
| exitMs | 320ms | Exit duration |
| enterMs | 640ms | Entrance duration |
| overMs | 420ms | Moment overshoot reaches 1.08 |
| Displacement | ±52px | Exit -52*dir, entrance +52*dir |
| Exit scale | 0.92 | ScaleX/ScaleY synchronized |
| Overshoot | 1.08 | ScaleX/ScaleY synchronized, then settles to 1.0 |

### 5.3 Language Switch Notification Sequence Fix

**Problem**: `MainFormViewModel.OnSelectLanguage` original sequence was `SelectedLanguage → IsBusy → CurrentState (triggers AnimateViewTransition) → OnPropertyChanged`, causing `SmartModeInfoTitle` and other bindings to still show old language cache during the switch animation.

**Fix**: All 16 `OnPropertyChanged(...)` notifications are moved before the `CurrentState` assignment:

- 5 button texts: SmartButtonText, GUIButtonText, ConsoleButtonText, BackButtonText, ExitButtonText
- 2 language panel fields: LanguageInfoTitle, LanguageInfoDesc
- 4 language description fields: ChineseInfoTitle/Desc, EnglishInfoTitle/Desc
- 4 mode description fields: SmartModeInfoTitle/Desc, ProModeInfoTitle/Desc, ConsoleModeInfoTitle/Desc
- Only then execute `IsBusy = true` and `CurrentState = MainFormViewState.ModeSelection`

### 5.4 Cached Instance Language Refresh

`ProModeView.Initialize` and `SmartModeView.Initialize` add a `language` parameter, synchronizing `_viewModel.Language` even when `_initialized=true` (NavigationCache reuse):

```csharp
// ProModeView: refresh before the _initialized guard
if (!string.IsNullOrEmpty(language) && _viewModel != null)
{
    _viewModel.Language = language;
}
if (_initialized) return;

// SmartModeView: early return when reusing cached instance
if (_initialized && _viewModel != null && !string.IsNullOrEmpty(language))
{
    _viewModel.Language = language;
    return;
}
```

### 5.5 Impact Scope

`MainFormView.xaml.cs` PlayElementSwitch, `MainFormViewModel.cs` OnSelectLanguage, `ProModeView.xaml.cs` Initialize, `SmartModeView.xaml.cs` Initialize.

## 6. Smart Mode Status Text Position Fix

V1.5.29.0 fixes the issue where the Smart mode UWP status text was squeezed to the bottom-right corner and flew out.

### 6.1 Problem

SmartModeView's UWP status text (StatusText) during the shell entrance animation, because `ProgressAnchor.ActualHeight/ActualWidth` layout was not yet complete, the position calculation returned wrong coordinates, causing the text to be positioned at the bottom-right corner or even fly out of the visible area.

### 6.2 Fix

`SmartModeView.BeginInvokeUpdateStatusTextPositionWithRetry` adds three layers of protection:

| Protection Mechanism | Implementation | Effect |
|----------------------|----------------|--------|
| Retry mechanism | Up to 25 times, 80ms interval | Covers 1000ms shell entrance animation, waits for layout completion |
| Layout completion check | `ActualHeight/ActualWidth <= 0` returns false | Avoids using incomplete coordinates |
| Self scale check | `Math.Abs(s - 1.0) > 0.01` returns false (V1.5.28.17) | Does not compute position during animation |
| X upper bound check | `targetX < ActualWidth` | Prevents text from flying off the right edge |

`UpdateStatusTextPosition` schedules the next retry timer when `success == false`, until layout completes or retry limit is reached.

### 6.3 Retry Parameter Evolution

| Version | Retry Count | Interval | Coverage Duration |
|---------|-------------|----------|-------------------|
| V1.5.28.9 (initial) | 5 | 50ms | 250ms (insufficient to cover 1000ms shell animation) |
| V1.5.28.17 (current) | 25 | 80ms | 2000ms (fully covers 1000ms shell animation) |

### 6.4 Impact Scope

`SmartModeView.xaml.cs` BeginInvokeUpdateStatusTextPositionWithRetry, UpdateStatusTextPosition.

## 7. Keyboard Focus and Navigation Anti-Bounce Unification

V1.5.29.0 fixes the issue where the main window's right-side explanatory text did not respond to keyboard focus, and uses a unified navigation lock to eradicate flashback during quick switching.

### 7.1 Keyboard Focus Fix

**Problem**: `MainFormView.AttachInfoHover` only bound the `MouseEnter` event — when keyboard Tab focus switched to a button, the right-side explanatory text did not update.

**Fix**: Extracts the common hover logic into a `focusHandler`, shared by `MouseEnter` and `GotFocus`:

```csharp
System.EventHandler<RoutedEventArgs> focusHandler = (s, args) =>
{
    try
    {
        if (_isPanelSwitching) return;
        int currentIndex = isLangPanel ? _currentLangIndex : _currentModeInfoIndex;
        if (index == currentIndex) return;
        // ... shared logic
    }
    catch (Exception ex) { /* logging */ }
};

btn.MouseEnter += (s, args) => focusHandler(s, args);
btn.GotFocus += (s, args) => focusHandler(s, args);
```

All 5 buttons (ChineseBtn, EnglishBtn, SmartModeBtn, ProModeBtn, ConsoleModeBtn) bind both events.

### 7.2 Unified Navigation Lock

**Problem**: ProModeView used a local `_isSwitching` flag for anti-bounce, other views had no anti-bounce, causing exit animation interruption during quick switching and `DiscreteDoubleKeyFrame` start value jumps, producing flashback.

**Fix**: Uses the `ViewManager.IsNavigating` public property (exposing the internal `_isNavigating` field) to establish a unified navigation lock:

- ProModeView removes the local `_isSwitching` flag, uniformly uses `ViewManager.IsNavigating`
- All navigation entry points reject new requests during animation

### 7.3 5 Navigation Entry Point Anti-Reentry Checks

| # | File | Method | Behavior |
|---|------|--------|----------|
| 1 | SmartModeView.xaml.cs | OnReturnToProRequested | `if (ViewManager.Current.IsNavigating) return;` |
| 2 | SmartModeView.xaml.cs | OnShowUndoViewerRequested | `if (ViewManager.Current.IsNavigating) return;` |
| 3 | ExportHistoryView.xaml.cs | OnCloseRequested | `if (ViewManager.Current.IsNavigating) return;` |
| 4 | ExportHistoryView.xaml.cs | OpenSolutionDetail | `if (ViewManager.Current.IsNavigating) return;` |
| 5 | SolutionDetailView.xaml.cs | OnCloseRequested | `if (ViewManager.Current.IsNavigating) return;` |

Additionally, ProModeView's OnShowHistoryRequested (line 886) and another navigation point (line 910) use the same guard, all tagged V1.5.28.23.

### 7.4 Impact Scope

`MainFormView.xaml.cs` AttachInfoHover, `ViewManager.cs` IsNavigating, `ProModeView.xaml.cs`, `SmartModeView.xaml.cs`, `ExportHistoryView.xaml.cs`, `SolutionDetailView.xaml.cs`.

## 8. Starfield Parallax Performance Optimization (Aurora Layer +50%)

V1.5.29.0 fixes the severe frame drop issue during starfield parallax, replacing star glow with aurora layer boost as visual feedback.

### 8.1 Problem

The original scheme enabled SoftGlow (soft glow) and DiffractionSpike (diffraction spikes) for near stars during parallax, but both costs scale linearly with star count:

- `DrawSoftGlow` requires PushTransform + DrawGeometry per star
- `PushTransform/DrawGeometry` causes severe frame drops with large star counts

### 8.2 Fix

**Skip SoftGlow and DiffractionSpike**: Both branches are skipped during parallax (`isParallaxCycling == true`):

```csharp
bool isParallaxCycling = (_parallaxState == ParallaxState.Cycling);

// SoftGlow branch: skip during parallax
if (!isParallaxCycling && star.HasSettled && ...) { ... }

// DiffractionSpike branch: skip during parallax
if (!isParallaxCycling && AuroraRenderEngine.CurrentTier >= PerformanceTier.Performance && ...) { ... }
```

**DrawAurora aurora layer +50% alpha boost**: As a visual feedback replacement, with fixed cost independent of star count:

```csharp
double parallaxBoost = 1.0;
if (_parallaxState == ParallaxState.Cycling)
{
    // smoothstep smoothing: ramp up 0→25%, hold 25-75%, ramp down 75-100%
    double pSmooth = ...;
    parallaxBoost = 1.0 + pSmooth * 0.5;  // max 1.5 (+50%)
}
localAlpha *= parallaxBoost;
```

### 8.3 smoothstep Smoothing (V1.5.28.27)

`parallaxBoost` uses actual animation time progress `t` (0→1) with smoothstep to compute a trapezoidal curve:

| Phase | t Range | pSmooth | parallaxBoost |
|-------|---------|---------|---------------|
| Ramp up | 0% ~ 25% | 0 → 1 | 1.0 → 1.5 |
| Hold | 25% ~ 75% | 1 | 1.5 |
| Ramp down | 75% ~ 100% | 1 → 0 | 1.5 → 1.0 |

Avoids brightness discontinuity when parallax transitions from Cycling to Idle.

### 8.4 Scheme Comparison

| Feedback Mechanism | Cost Characteristic | Performance | Visual Effect |
|--------------------|---------------------|-------------|---------------|
| SoftGlow + DiffractionSpike (original) | Linear with star count | Severe frame drops | Per-star glow visible |
| DrawAurora alpha +50% (new) | Fixed cost, independent of star count | Fluid | Aurora layer overall boost |

### 8.5 Impact Scope

`AuroraStarfield.cs` DrawStars (SoftGlow/DiffractionSpike branches), DrawAurora (parallaxBoost computation).

## 10. Known Limitations

### 10.1 Parallax Depth Subjective Perception Differences

The 7-level depth mapping depth values (0.00 ~ 1.00) are calibrated based on visual subjective perception. On extreme high refresh rate (240Hz+) displays, parallax interpolation may differ slightly from design intent, but visual consistency is better than before.

### 10.2 Aurora Layer Boost Performance Boundary

The DrawAurora +50% alpha boost is a fixed cost, but in Eco tier (software rendering or remote session), the aurora layer itself may already be degraded, and the boost effect may be less noticeable.

### 10.3 Dialog Background Pass-Through Hit Testing

After the dialog root `UserControl` removes the `Background` attribute, blank areas do not participate in hit testing, and mouse events pass through to the shell starfield. This is intentional visual consistency design, but means right-click and other events on dialog blank areas will not be intercepted by child elements.

### 10.4 Navigation Anti-Bounce Boundary

The `ViewManager.IsNavigating` unified navigation lock rejects all new navigation requests during exit animation playback. If the user quickly clicks different views during animation, only the first request executes; subsequent requests are silently dropped (no error prompt).
