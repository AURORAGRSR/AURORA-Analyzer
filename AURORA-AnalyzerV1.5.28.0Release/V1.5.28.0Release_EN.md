# AURORA-Analyzer V1.5.28.0 Release Notes

***

## 1. Welcome to V1.5.28.0

Thank you for choosing AURORA-Analyzer! V1.5.28.0 is a comprehensive reshaping release for the view system and animation language. We have completely unified the Aurora animations to a single parameter contract, established a brand-new unified layout vocabulary for all views, and built three new dedicated views for Smart Mode, History management, and Solution details — bringing a coherent and refined visual experience to every analysis, every comparison, and every repair.

***

## 2. Completely Unified Aurora Animations

### A Consistent Visual Language

Previously, each view's enter, exit, and switch animation parameters varied — some windows converged from 1.1x scale, others from 1.15x; some exited by scaling down, others by scaling up; control staggered enter durations and overshoot amplitudes were inconsistent. V1.5.28.0 converges all animations to a unified contract:

- **Window Enter**: Gracefully converges from 1.15x scale to 1.0x, with a fade-in, like a star emerging from afar
- **Window Exit**: First wind-ups to 0.97x, then scales up to 1.15x to leave, with a fade-out, like a star dissolving into the distance
- **Control Enter**: Each control first overshoots to 1.07x, then converges to 1.0x with jelly elasticity, with adjacent controls entering at an 80ms rhythm
- **Modal Dialogs**: Spring in from 0.92x to 1.07x then converge to 1.0x, and wind-up scale-up to leave on exit

The core visual metaphor of this animation is "emerging from the cosmos, dissolving into the cosmos" — whether it's the main window, dialogs, or the Smart Mode, History, and Solution views, all share the same breathing rhythm.

### 1500ms Fallback Guarantee

We added a 1500ms fallback timer to all control staggered enters. Even if animation timers fail to fire due to system congestion, controls will force-restore to visible state after 1.5 seconds, fundamentally eliminating the previously observed console background magnification issue.

## 3. New Unified View Layout Design

### A Consistent Visual Skeleton

V1.5.28.0 establishes a unified layout vocabulary for all views: borderless transparent window, starfield background layer, 24-pixel margin content area, 3:2 left-right split, frosted glass container, Aurora self-drawn scrollbar. Whether it's the main window, PRO mode, or the new Smart Mode, History, and Solution views, all follow the same layout specification, bringing a coherent and consistent visual experience.

### Translucent Frosted Glass Containers

All content sections use AuroraFrostedGlassBorder frosted glass containers, and modal dialogs use the AuroraFrostedGlassCard rounded glass style (CornerRadius=12), presenting a unified translucent quality. The Aurora self-drawn scrollbar is replicated across all views, providing consistent interaction details.

***

## 4. Smart Mode's New Dedicated View

### Independent Window, Focused Experience

Smart Mode now has its own dedicated view, SmartModeView. It has been separated from the original PRO mode's inline panel into a 1000×700 independent window, giving you a more focused and spacious operating environment during intelligent analysis.

### Console and Repair Items Side by Side

SmartModeView adopts a 3:2 left-right split layout: the left side is the real-time scrolling console output, and the right side is the executable repair items menu. Each repair item is displayed as a two-row card — the first row shows the command name and execution status mark, and the second row shows the rule name and tags for risk level, permission requirements, and authorization requirements, making information clear at a glance.

### Rounded Glass Modals

Authorization queries, decision confirmations, engine input, and other modal dialogs are all upgraded to the rounded glass style, consistent with the overall visual language. When returning to PRO mode, smooth switch-out/switch-in transition animations play between the two views.

***

## 5. New History View

### History Archives at a Glance

The brand-new ExportHistoryView history view lets you easily manage all log analysis archives. The left list shows each history record's archive time, health score, log type, and event counts (Critical/Error/Warning); the right detail area shows the health overview panel, basic information, and fingerprint signals.

### Fingerprint Signals, Precise Comparison

Each history record contains strong signal (EventId | Source × Count) and weak signal (Keyword × Count) fingerprint information. Click the "Detect Current" button, and the system will fingerprint-match the current logs against the selected history, generating a detailed comparison report — including health score comparison, event count comparison, strong signal hit/miss status with historical vs current count changes, weak signal comparison, and matched fix solutions.

### One-Click Entry to Solutions

If the detection matches successfully and solutions exist, the system will ask whether you want to view details. Select "Yes" to enter the brand-new Solution view.

***

## 6. New Solution View

### Metric Comparison, Clear and Intuitive

The brand-new SolutionDetailView solution view displays in a 3:2 left-right split: the left side shows the history-vs-current metric comparison table (Health, EventCount, Critical, Error), match score, and solution list; the right side shows the complete details of the selected rule — description, causes, solutions, recommended action, and each fix command's name, type, risk level, command text, permission requirements, and execution mode.

### Solution Switching, Smooth and Natural

When selecting different rules in the solution list, the right detail area plays a directional slide transition animation, and the list item simultaneously triggers a micro-rebound feedback, making every switch full of quality.

### One-Click Repair with Rollback Support

Click the "Execute Fix" button to open the fix execution dialog, one-click execute all fix commands for the selected rule, with Undo manager rollback support.

## 7. Bug Fixes

### Console Background Magnification Issue

Fixed an issue where AURORACONSOLE's background appeared abnormally magnified after shrinking. The root cause was the enter animation's scale transform getting stuck at an intermediate value when timers failed to fire, causing the blur layer's crop area to be too small. The fix introduced a unified 1500ms fallback timer across all views to force-reset transform states.

### Smart Mode Echo Failure

Fixed an issue where Smart Mode's dialog displayed blank after execution. The root cause was syncHash key name mismatches between the ViewModel and the engine, causing authorization signal failure and engine blocking. After the fix, key names are fully aligned, and authorization, decision, elevation, and exported logs dialogs all echo correctly.

### False Smart Mode Trigger

Fixed an issue where running a previously executed Smart Engine after running the PRO Engine and returning to the main window incorrectly launched the Smart Mode view. The root cause was residual smart menu data in the PowerShell session. After the fix, residual state is cleaned at the start of each new analysis session.
