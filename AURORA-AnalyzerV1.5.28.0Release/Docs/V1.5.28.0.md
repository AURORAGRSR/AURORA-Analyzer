## 1. 版本概述

V1.5.28.0 是 AURORA-Analyzer 视图体系与动效语言的全面重塑版本。本次更新围绕五大核心领域展开：

1. **完全统一设计的极光动效**：将所有视图的窗口级与控件级动效统一到同一套参数契约，覆盖入场、退场、切换、交错入场、模态进出全生命周期
2. **全新统一设计的视图布局**：建立无边框透明窗口外壳 + AuroraStarfield 星空背景 + AuroraFrostedGlassBorder 玻璃容器 + 3:2 左右分栏 + 极光滚动条的统一布局语汇
3. **智能模式全新的专属视图**：SmartModeView 从原 ProModeView 内嵌面板重构为 1000×700 独立窗口，采用控制台与可执行修复项左右分栏布局，圆角玻璃模态对话框
4. **全新的历史视图**：ExportHistoryView 提供历史归档列表、健康概览、指纹信号、当前对比与一键检测入口
5. **全新的解决方案视图**：SolutionDetailView 提供指标对比表格、解决方案列表、规则详情与一键修复执行入口

在动效统一方面，V1.5.28.0 将此前各视图参差不齐的入场/退场/切换参数收敛为统一契约：

| 动效层级 | 统一参数 |
|----------|----------|
| 窗口入场 | Scale 1.15→1.0，600ms AuroraCustomBackEase EaseOut + Opacity 0→1，600ms CubicEase EaseOut |
| 窗口退场 | Scale 1.0→0.97 蓄力（80ms QuadraticEase）→0.97→1.15 放大离开（720ms QuadraticEase）+ Opacity 1→0，800ms CubicEase EaseOut |
| 控件交错入场 | Scale 0→1.07（450ms CubicEase EaseOut）→1.07→1.0 果冻收敛（525ms QuarticEase EaseOut），相邻 tile 延迟 80ms |
| 模态入场 | 0.92→1.07→1.0 三段 + Y 24→0，360ms CubicEase + 525ms QuarticEase 收敛 |
| 模态退场 | 1.0→0.97 蓄力（80ms）→0.97→1.15 离开（720ms）+ Y 0→-16 + 800ms 淡出 |
| 兜底定时器 | 1500ms 后强制 Opacity=1、ScaleX/ScaleY=1.0、Translate 归零 |

在视图布局方面，V1.5.28.0 为 SmartModeView、ExportHistoryView、SolutionDetailView 三个全新视图建立了统一的布局语汇：无边框透明窗口、AuroraStarfield 星空背景层、Grid Margin=24 内容区、3:2 左右分栏、AuroraFrostedGlassBorder 玻璃容器、AuroraFrostedGlassCard 圆角模态、极光自绘滚动条。

本次更新是一个"视图体系全面重塑、动效语言完全统一、底层接口保持兼容"的版本。所有面向用户的命令行参数、环境变量接口和 syncHash 同步机制均保持完全兼容，确保现有脚本和工作流无需修改即可运行。

## 2. 完全统一的极光动效设计

V1.5.28.0 将所有视图的动效统一到同一套参数契约，涵盖窗口级、控件级和模态级三个层级。

### 2.1 窗口级入场动效

所有窗口（SplashScreenView、MainFormView、ProModeView、SmartModeView、ExportHistoryView、SolutionDetailView、ElevationDialogView、SessionRestoreDialogView、PerformanceUpgradeDialogView、PermissionInfoView）的入场统一为：

- **ScaleTransform**：1.15 → 1.0，600ms，AuroraCustomBackEase（EaseOut）
- **Opacity**：0 → 1，600ms，CubicEase（EaseOut）
- **RenderTransformOrigin**：Window 级别 `0.5,0.5`，TransformGroup 内含 ScaleTransform + TranslateTransform
- **XAML 预置**：ScaleTransform 预设 `ScaleX="1.15" ScaleY="1.15"` 避免首帧闪烁
- **星空锁定**：入场期间 `StarfieldBg.IsWindowAnimating = true`，动画完成后解锁

AuroraCustomBackEase 实现原始 PowerShell 公式 `f(t) = 1 - (1-t)³·(1+3t)`，通过 `EaseInCore` 返回 `t³·(4-3t)` 配合 `EasingMode.EaseOut`。该实现刻意避开了 WPF 内置 BackEase 在 t=0 处取值为 0 的特性（会导致缩放通道首帧静止）。

PlayMainWindowEnter 在 600ms 入场完成后追加 V1.5 液态玻璃微回弹：1.0→1.03（120ms QuadraticEase EaseOut）→1.03→1.0（280ms QuarticEase EaseOut），通过 600ms 延迟的 DispatcherTimer 触发。

### 2.2 窗口级退场动效

所有窗口的退场统一为"蓄力—放大离开—淡出"三段式：

| 阶段 | Scale | 时长 | 缓动 | Opacity |
|------|-------|------|------|---------|
| 蓄力 | 1.0 → 0.97 | 80ms | QuadraticEase EaseOut | — |
| 放大离开 | 0.97 → 1.15 | 720ms | QuadraticEase EaseOut | — |
| 淡出 | — | 800ms | CubicEase EaseOut | 1 → 0 |

退场流程：设置 `IsHitTestVisible = false` 防止重复触发 → `StarfieldBg.IsWindowAnimating = true` 锁定星空 → 启动蓄力+放大+淡出并行动画 → 完成后执行收尾回调（StopAnimation + Close + Shutdown）。退场采用"放大冲出"而非"缩小消退"，窗口像星辰向观察者飞来后消散，与星空主题呼应。

### 2.3 控件级交错入场动效

所有视图的控件交错入场统一为 80ms 交错 + 450ms 主动画 + 525ms 果冻收敛：

- **交错延迟**：相邻 tile 延迟 80ms（`staggerMs = 80`），通过 DispatcherTimer 逐个触发
- **主动画**：Scale 0 → 1.07，450ms，CubicEase EaseOut；Opacity 0 → 1，450ms CubicEase EaseOut；Y 偏移 100 → 0
- **果冻收敛**：主动画到 1.07 后，1.07 → 1.0，525ms，QuarticEase EaseOut
- **玻璃块特殊处理**：玻璃材质 tile 的 Scale 起点从 0 改为 1.0（避免逐帧模糊纹理重计算导致的抖动），仍以 1.07 为过冲目标

该参数契约已在 SmartModeView.PlayControlEnterAnimation、ExportHistoryView.PlayControlEnterAnimation、SolutionDetailView.PlayControlEnterAnimation 中统一实现。AnimationHelper.PlayMetroStaggerEnter 作为可复用辅助方法（默认值 staggerMs=30、durationMs=320、offsetY=60，Windows 8.1 Metro 原始值），各视图在调用时覆盖为 80/450/100 的统一标准。

### 2.4 模态对话框动效

模态覆盖层（ModalOverlay、UserInputOverlay、MessageOverlay）的进出动效统一为三通道 UWP 动画：

**入场**：
- 覆盖层 Opacity 0 → 1
- 内容 Scale 0.92 → 1.07 → 1.0（三段：0.92→1.07 主动画 360ms CubicEase EaseOut，1.07→1.0 果冻收敛 525ms QuarticEase EaseOut）
- 内容 Y 24 → 0

**退场**：
- 内容 Scale 1.0 → 0.97 蓄力（80ms QuadraticEase）→ 0.97 → 1.15 离开（720ms QuadraticEase）
- 内容 Y 0 → -16
- 覆盖层 Opacity 1 → 0，800ms CubicEase EaseOut

该契约在 SmartModeView.AnimateModalOverlay、ExportHistoryView.ShowGlassMessage/ShowGlassConfirm、SolutionDetailView 的模态方法中统一实现。

### 2.5 1500ms 兜底定时器

所有视图的控件交错入场均配备 1500ms 兜底定时器。该定时器在触发后强制停止所有 tile 动画，并重置 `Opacity = 1`、`ScaleX/ScaleY = 1.0`、`Translate X/Y = 0`，确保即使 Dispatcher 定时器因线程繁忙或窗口 Hide/Show 未触发，控件也能保证可见性。

该机制是 ConsoleBox 背景放大缺陷的直接修复方案——当入场动画的 ScaleTransform 卡在中间值（如 0 或 1.07）时，BlurLayer 的 CroppedBitmap 裁剪区域过小，拉伸后产生放大效果。1500ms 兜底定时器强制重置变换状态，从根本上消除该问题。

### 2.6 视图切换动效

ProModeView 与 SmartModeView、ExportHistoryView 与 SolutionDetailView 之间的视图切换采用专属的切换动效（区别于冷启动入场）：

**切出（PlaySwitchOutAnimation）**：
- Scale 1.0 → 0.97 蓄力（80ms QuadraticEase EaseOut）→ 0.97 → 1.15 离开（720ms QuadraticEase EaseOut）
- Opacity 1 → 0，800ms CubicEase EaseOut
- 完成回调中构造并显示目标窗口

**切入（PlaySwitchInAnimation）**：
- Scale 起点重置为 1.1（区别于冷启动的 1.15，更轻量的再入场曲线）
- Scale 1.1 → 1.0，600ms CubicEase EaseOut
- Opacity 0 → 1，500ms CubicEase EaseOut
- 重新注册 `AuroraMaterialPipeline.Current.SetBackgroundSource(StarfieldBg)` 恢复玻璃材质背景源
- 恢复轮询 `_viewModel.ResumePolling()`

## 3. 全新统一设计的视图布局

V1.5.28.0 为所有视图建立了统一的布局语汇，覆盖窗口外壳、背景层、内容容器、分栏比例、滚动条和模态层。

### 3.1 无边框透明窗口外壳

所有视图共享无边框透明窗口外壳：

- `WindowStyle="None"`、`AllowsTransparency="True"`、`Background="Transparent"`
- `ResizeMode="NoResize"`、`Topmost="False"`、`RenderTransformOrigin="0.5,0.5"`
- 预装 `TransformGroup`（ScaleTransform + TranslateTransform）
- 大多数视图初始 `Opacity="0"`，由入场动画驱动淡入

窗口尺寸约定：MainForm 400×480、SplashScreen 420×190、Elevation/ProMode 750×750、PermissionInfo 520×520、SmartMode/ExportHistory/SolutionDetail 1000×700。

### 3.2 AuroraStarfield 星空背景层

AuroraStarfield 是所有视图的通用背景层，同时是 AuroraMaterialPipeline 的注册背景源（`SetBackgroundSource(StarfieldBg)`）。它暴露 `IsWindowAnimating` 属性，在窗口入场/退场/切换动画期间切换到降级渲染模式（减少星星数量和绘制频率、跳过呼吸效果和流星特效），降低 GPU 负载。

可选属性包括 `StatusText`、`StatusTextX/Y`、`StatusTextAlignment`、`StarCount`。

### 3.3 AuroraFrostedGlassBorder 玻璃容器

AuroraFrostedGlassBorder 是通用内容容器，有两种用法：

- **裸用**：`CornerRadius=8`，`BorderThickness=0`，用于内容分区（控制台区、菜单区、列表区、详情区）
- **AuroraFrostedGlassCard 样式**：`CornerRadius=12`，用于模态对话框和弹出层，提供更强的玻璃质感和圆角

它渲染 4 层玻璃效果（背景层 + 顶部高光描边 + 内部散射层），与 AuroraConsoleBox 的配色保持一致。

### 3.4 3:2 左右分栏布局

SmartModeView、ExportHistoryView、SolutionDetailView 三个全新视图的主内容区统一采用 3:2 左右分栏：

- 列定义：`3*/12/2*`（左栏 3 份、12px 间距、右栏 2 份）
- 左栏：主操作区（控制台 / 历史列表 / 对比表格）
- 右栏：辅助信息区（可执行修复项 / 历史详情 / 解决方案详情）

内容卡片使用半透明 `#11000000` 背景，CornerRadius=6，Padding 12-14。

### 3.5 极光自绘滚动条

统一的 AuroraScrollBarStyle + AuroraScrollViewerStyle 在 SmartModeView、ExportHistoryView、SolutionDetailView、ProModeView 中复用（ProModeView 为规范版本）：

- 宽度 10-14px，CornerRadius=5
- 轨道 `#19141E32`，边框 `#2D6496DC` 0.5px
- 滑块渐变 `#64B0D2FF` → `#5096C8FF`
- 悬停 `#82B4E1FF` / `#94C4E5FF`
- 拖拽 `#AAC8F0FF` / `#B8D4F5FF`
- 滑块模板含 40% 高度的顶部高光 `#40FFFFFF` → `#00FFFFFF` 和拖拽径向辉光 `#28C8E6FF`

### 3.6 模态覆盖层统一

所有主要视图共享模态覆盖层模式：

- 根级 `Grid x:Name="...Overlay" Background="#800A1428" Visibility="Collapsed"`
- 内含 `AuroraFrostedGlassBorder`，应用 `AuroraFrostedGlassCard` 样式（CornerRadius=10-12，Padding=24-28，MinWidth=360-400，MaxWidth=520-580，居中）
- 内部结构统一为 3 行网格：标题（16pt 加粗强调色）+ 可滚动正文（12pt，LineHeight=20）+ 居中的确认/取消 AuroraButton 行（140×40，6px 间距）

### 3.7 标题栏与底部操作栏

- **标题栏**：3 列 `Auto/*/Auto` 网格，左侧返回/操作按钮，中央 AuroraTextBlock 标题（`AnimatedText` 绑定），右侧操作按钮水平 StackPanel
- **底部操作栏**：右对齐 StackPanel 或多列 Grid，统一 32-40px 高度的 AuroraButton，8-12px 右间距

## 4. 智能模式专属视图 SmartModeView

SmartModeView 是智能模式的全新专属视图，从原 ProModeView 内嵌面板重构为 1000×700 独立窗口。

### 4.1 窗口架构

- 1000×700 无边框透明窗口，`WindowStartupLocation="CenterScreen"`
- 根 Grid 层叠 AuroraStarfield 星空背景 + Margin=24 内容区
- 内容区 4 行定义：标题栏（Auto）/ 左右分栏主体（*）/ 进度条（Auto）/ 底部操作栏（Auto）

### 4.2 左右分栏布局

主体区 3:2 左右分栏（`3*/12/2*`）：

- **左栏 ConsoleGlass**：AuroraFrostedGlassBorder（CornerRadius=8）包裹 AuroraConsoleBox，绑定 `ConsoleLines`，FontSize=13。控制台固定高度等于主体全高，确保 BlurLayer 采样稳定
- **右栏 MenuGlass**：AuroraFrostedGlassBorder（CornerRadius=8，Padding=14,12）包含 2 行网格：菜单标题"可执行修复项"（14pt 加粗，#B0D0FF）+ ScrollViewer 中的 ItemsControl 绑定 `SmartMenuItems`

### 4.3 菜单项卡片布局

每个 SmartMenuItem 通过 DataTemplate 渲染为两行卡片（Border，Margin 2,3，Padding 12,10，CornerRadius=6，边框 `#3064788C`，背景 `#200A1428`，Cursor=Hand）：

- **第一行 命令信息**：3 列网格（Auto/*/Auto）
  - 索引号（13pt 加粗，#82B4E1FF，MinWidth=20）
  - 命令名（13pt 白色，CharacterEllipsis 截断）
  - "✓"执行标记（14pt 加粗 #60E090，仅 IsExecuted=true 时可见）
- **第二行 规则名 + 标签**：2 列网格（*/Auto）
  - 规则名（11pt #8090A8，截断）
  - 水平 StackPanel 标签（10pt）：RiskLevelText（#A0C4E0）、AdminTag（#E0B060）、AuthTag（#60C080），各 6px 右间距

状态样式通过 DataTrigger：IsExecuted=True → Opacity 0.4；IsExecuting=True → Opacity 0.6。

### 4.4 圆角玻璃模态对话框

两个根级覆盖层：

- **ModalOverlay**（背景 `#800A1428`）：承载 ModalGlass，应用 AuroraFrostedGlassCard 样式，Padding=28，MinWidth=400，MaxWidth=580，MaxHeight=520，居中。3 行网格：标题（16pt 加粗 #B0D0FF）+ 可滚动消息（12pt，LineHeight=20）+ 居中确认/取消按钮行
- **UserInputOverlay**（引擎输入对话框）：承载 UserInputGlass，MinWidth=400，MaxWidth=520。4 行网格：标题"引擎输入" + 提示语 + TextBox（Consolas 13pt，`#1AFFFFFF` 背景，`#4064788C` 边框，Padding 10,8）+ 提交/取消按钮

ModalGlass 和 UserInputGlass 均升级为 AuroraFrostedGlassCard 样式（CornerRadius=12），实现统一的圆角玻璃设计。

### 4.5 底部操作栏

4 列网格：左侧 AuroraTaskHUD（210×40，IsHitTestVisible=False）+ ExecuteStopButton（140×36）+ ClearConsoleButton（120×36）+ ExportLogButton（120×36）。

### 4.6 与 ProModeView 的交互流程

SmartModeView 作为独立窗口由 ProModeView 拥有（`smartView.Owner = this`）：

1. ProModeViewModel 触发 `ShowSmartModeRequested` 事件（取代原 `IsSmartMenuVisible` 标志）
2. ProModeView 播放切出动效（PlaySwitchOutAnimation），完成回调中构造 SmartModeView 并 Show
3. SmartModeView.OnWindowLoaded 调用 `_viewModel.StartPolling()`（SmartModeViewModel 接管 syncHash 交互，避免双 ViewModel 冲突），然后播放窗口入场动效
4. 返回时 SmartModeView 播放退场动效并 Close
5. ProModeView.OnSmartModeClosed 播放切入动效，重新注册玻璃材质背景源，恢复轮询

## 5. 全新历史视图 ExportHistoryView

ExportHistoryView 是日志历史管理的全新视图，提供历史归档浏览、健康概览、指纹信号查看与当前对比检测入口。

### 5.1 布局设计

1000×700 无边框透明窗口，`WindowStartupLocation="CenterOwner"`。根 Grid 层叠 AuroraStarfield（StarCount=100）+ Margin=24 内容区，3 行定义：

- **行 0 标题栏**：BackBtn（80×30）+ TitleLabel（18pt 加粗，AnimatedText 绑定）
- **行 1 主体 3:2 左右分栏**：左栏历史列表 + 右栏历史详情
- **行 2 底部操作栏**：DetectBtn / ExportBtn / OpenDirBtn / DeleteBtn

### 5.2 历史列表（左栏）

ListSection（AuroraFrostedGlassBorder，CornerRadius=8）：标题行（列表标题 + RefreshBtn 60×24）+ ListBox 绑定 `Entries`/`SelectedEntry`。空状态通过 InverseBooleanToVisibilityConverter 显示提示文本。

每条历史记录通过 ItemTemplate 渲染为垂直 StackPanel：

- **第一行**：归档时间（`{0:yyyy-MM-dd HH:mm}`，11pt 加粗白色）
- **第二行**：水平 StackPanel — 健康分数彩色 Ellipse（8×8，HealthScoreToBrushConverter）+ LogType（10pt 弱化色）+ "·" + 健康分数数值（11pt 加粗，彩色）+ "·" + 事件计数序列（CriticalEvents 红色"C"、ErrorEvents 琥珀色"E"、WarningEvents 强调色"W"）

ListBoxItem 模板使用 Border（CornerRadius=6，Padding 10,8），悬停 `#22FFFFFF`，选中 `#33FFFFFF` + AuroraAccentBrush 边框。

### 5.3 历史详情（右栏）

DetailSection（AuroraFrostedGlassBorder，CornerRadius=8）2 行网格：

- **顶部 HealthOverviewPanel**：Border（背景 `#11000000`，CornerRadius=6，Padding 14,10），展示健康分数大数值（28pt 加粗 + 彩色 Ellipse 圆点）、等级/日志类型/日期范围堆叠、Critical/Error/Warning 计数列
- **底部 DetailScrollViewer**：两张半透明卡片
  - **基本信息卡**：归档时间 / 总事件数 / 文件列表
  - **指纹信息卡**：StrongSignals（EventId | Source × Count 列表）、WeakSignals（Keyword × Count 列表）、Hash 字符串

### 5.4 检测与对比入口

## 7. 视图切换与窗口交接机制

V1.5.28.0 采用独立的窗口交接机制取代原地的可见性切换，涵盖 ProMode↔SmartMode、ExportHistory↔SolutionDetail 两对视图切换。

### 7.1 独立窗口 ViewModel 交接

模式切换使用"隐藏宿主 + 显示从属窗口 + 关闭后恢复"模式：

- 宿主视图播放切出动效后 Hide
- 构造从属窗口，设置 Owner = 宿主
- 从属窗口接管 syncHash 交互（避免双 ViewModel 冲突）
- 从属窗口关闭时宿主恢复：Show + 切入动效 + 重新注册 AuroraMaterialPipeline 背景源 + 恢复轮询

### 7.2 ProModeView ↔ SmartModeView 切换

- ProModeViewModel 触发 ShowSmartModeRequested（取代原 IsSmartMenuVisible 标志）
- ProModeView.OnShowSmartModeRequested 播放 PlaySwitchOutAnimation，完成回调构造 SmartModeView 并 Show
- SmartModeView.OnWindowLoaded 调用 StartPolling，播放入场动效
- 返回时 SmartModeView.PlayWindowExitAnimation 退场并 Close
- ProModeView.OnSmartModeClosed 播放 PlaySwitchInAnimation，重新注册背景源，恢复轮询

### 7.3 ExportHistoryView ↔ SolutionDetailView 切换

- ExportHistoryView.OpenSolutionDetail 播放退场动效（Scale 1.0→1.15 + Opacity 1→0，500ms CubicEase）后 Hide
- 构造 SolutionDetailView，ShowDialog
- SolutionDetailView 关闭后 ExportHistoryView 恢复（Show + Scale 1.15→1.0 + Opacity 0→1，500ms）

### 7.4 背景源重注册

切入动效完成时调用 `AuroraMaterialPipeline.Current.SetBackgroundSource(StarfieldBg)` 重新注册玻璃材质背景源。这是因为窗口 Hide 期间背景源可能失效，重注册确保玻璃材质能正确采样星空背景。

## 8. 缺陷修复

### 8.1 ConsoleBox 背景放大问题

**问题**：AURORACONSOLE 在缩小后背景工作出现视觉异常，背景被放大了好几倍。根因是 ConsoleBox 入场动画的 ScaleTransform 残留——动画使用两个 DispatcherTimer 实现 0→1.07→1.0 的缩放效果，但当定时器因 Dispatcher 繁忙或窗口 Hide/Show 未触发时，ScaleTransform 卡在中间值（如 0 或 1.07），原兜底定时器仅重置 Opacity 未重置缩放，导致 BlurLayer 的 CroppedBitmap 裁剪区域过小，拉伸后产生放大效果。

**修复**：在 ProModeView.xaml.cs 的兜底定时器中，除重置 Opacity=1 外，额外添加 ScaleTransform.ScaleX/ScaleY=1.0 和 TranslateTransform.Y=0 的强制重置。该修复随后升级为所有视图统一的 1500ms 兜底定时器机制。

### 8.2 SmartMode 键名不匹配导致回显失败

**问题**：SmartModeViewModel 的 syncHash 键名与 SmartEngine 实际键名不匹配，导致授权信号失败、SmartEngine 阻塞在 WaitOne(30000) 30 秒超时，对话框因 Hashtable 解析错误显示空白。

**修复**：纠正 ProcessSyncHashSnapshot 中的键名（如 `SmartAnalysisAuthRequired` → `SmartAnalysisRequested`、`RequiresDecision` → `RequiresAuthorization`，移除 `MenuWaiting`），新增 `RequiresElevation` 检测和 `InputType=="UseExportedLogs"` 分支。修复 CloseModal 授权信号（如 `SmartAnalysisAuthorized=true` + `SmartAnalysisRequested=false` + SignalAuthorizationEvent()）。修复对话框显示（ShowDecisionModal 的 PendingCommand 解析、ShowResultModal 的 resultObj.ToString() 正确解析 ActionName/Result/Output/ExecutionTime，新增 ShowElevationModal 和 ShowExportedLogsModal）。

### 8.3 PROENGINE 误触发 SmartEngine

**问题**：在 PROENGINE 运行后返回主窗口，再运行先前执行过的 SMARTENGINE 时，错误地启动智能模式视图。根因是 PowerShell 会话中残留的 syncHash.SmartMenuItems 数据。

**修复**：在 ProModeViewModel 的 StartAnalysisAsync 方法中添加清理逻辑——每次新分析会话开始时清除 SmartMenuItems、ExecutedMenuIndices，重置签名，设置 IsSmartMenuVisible=false，确保干净状态，防止旧数据误触发。

## 10. 已知限制

### 10.1 视图切换的轻量再入场

PlaySwitchInAnimation 使用 1.1 起始缩放（而非冷启动的 1.15）和 CubicEase 缓动（而非 AuroraCustomBackEase），这是刻意的更轻量再入场曲线，与冷启动窗口入场有所区别。用户在频繁切换视图时可能注意到再入场比首次启动略快。

### 10.2 玻璃块动效起点

控件交错入场中，玻璃材质 tile 的 Scale 起点从 0 改为 1.0（避免逐帧模糊纹理重计算抖动），因此玻璃块的入场视觉效果与非玻璃 tile 略有不同——玻璃块没有从 0 放大的过程，而是从 1.0 过冲到 1.07 再收敛。

### 10.3 独立窗口的资源开销

SmartModeView、ExportHistoryView、SolutionDetailView 作为独立窗口，各自维护 AuroraStarfield 星空背景实例和 AuroraMaterialPipeline 背景源。在低配设备上，频繁的视图切换可能带来短暂的星空背景重建开销。
