## 1. Version Overview

V1.4.27.1 is a deep refinement release for the AURORA-Analyzer material system. The core of this update is the comprehensive refactoring of the V1.4.27.0 four-layer flat frosted glass rendering system (AuroraGlassMaterial) into the V5 nine-layer independent layered architecture, with repeated tuning of visual details such as glass edge highlights, color sampling layers, and hover transitions.

V1.4.27.0's AuroraGlassMaterial achieved frosted glass effects through a four-layer rendering pipeline (dual drop shadows, true blurred background, glass body gradient, surface overlay). This was a leap from WinForm GDI+'s inability to implement blur to WPF GPU-accelerated blur. However, in deep actual use, the system exposed multiple visual defects: stretched and distorted backgrounds inside the glass under certain conditions, hard circular rings at edges, hover highlights concentrating only at the four corners, flat color sampling without depth, noise brightness jumping once per second, and the main interface glass losing blur after window switching.

V1.4.27.1 resolves these issues through the following strategies:

- **V5 Nine-Layer Independent Rendering Architecture**: Decomposed the four-layer coupled pipeline into nine independent IMaterialLayer implementations, each computed independently and composited in order, sorted by the Order property.
- **IMaterialSurfaceHost Interface**: Controls connect to the V5 pipeline by implementing this interface, fully decoupled from rendering logic.
- **AuroraMaterialComposer**: Each V5 control holds an independent material compositor instance that schedules the nine-layer rendering.
- **Four Material Style Presets**: AuroraFluentGlass / LiquidGlass / Mica / Holographic, switchable at runtime.
- **Five-Level Blur Backend Fallback Chain**: DwmAcrylic → ShaderEffect → RTB → D3D9Ex → Solid, automatically selected based on system capabilities.
- **EaseInOutCubic Ceremonial Transition**: Hover glow gracefully blooms over 3 seconds with gentle deceleration at both ends.

Although the material system has undergone significant refactoring, V1.4.27.1 maintains full compatibility with V1.4.27.0. The UseV5Pipeline switch allows controls to switch between the V5 pipeline and V4 AuroraGlassMaterial. All command-line parameters, environment variables, syncHash communication protocols, and script interfaces remain unchanged.

## 2. V5 Material Pipeline Architecture

The V5 material pipeline adopts a four-layer architecture (L1-L4), each with clear responsibility boundaries.

### 2.1 L1 Backend Layer (Blur Backend)

The blur backend layer is responsible for capturing visual content behind the control and applying blur processing. V1.4.27.1 implements a five-level fallback chain:

| Backend | Implementation Status | Description |
|---------|----------------------|-------------|
| DwmAcrylicBackend | Implemented | Win11 DWM Acrylic/Mica, requires explicit window backdrop enablement |
| ShaderEffectBackend | Implemented | HLSL shader blur (CPU software rasterization) |
| RtbBlurBackend | Implemented | RenderTargetBitmap + BlurEffect |
| D3D9ExBackend | Reserved | Direct3D 9Ex hardware blur |
| SolidFallbackBackend | Reserved | Solid color fallback |

Backend selection logic detects platform capabilities through the IsAvailable interface. Remote sessions and virtual machine environments forcibly disable GPU backends, falling back to RTB software blur. DwmAcrylicBackend adds a _backdropApplied flag, only selected for windows that have explicitly called ApplyWindowBackdrop to enable Mica.

### 2.2 L2 Layer Layer (Material Layers)

The L2 layer defines nine independent rendering layers, each implementing the IMaterialLayer interface:

```csharp
public interface IMaterialLayer : IDisposable
{
    int Order { get; }
    string Name { get; }
    bool IsEnabled(MaterialRenderContext ctx);
    void Update(MaterialRenderContext ctx);
    void Render(DrawingContext dc, MaterialRenderContext ctx);
    void OnSizeChanged(Size newSize, double cornerRadius);
}
```

Each layer determines render participation through Order, independently judges through IsEnabled, updates internal state through Update (such as smooth transitions, animation progress), and draws to DrawingContext independently through Render. Layers are decoupled, with all parameters passed through MaterialRenderContext and MaterialStylePreset.

### 2.3 L3 Composer Layer (AuroraMaterialComposer)

AuroraMaterialComposer is the material compositor instance held by each V5 control. Its core responsibilities:

- Registering with AuroraMaterialPipeline on control Loaded, unregistering on Unloaded
- Calling Render on OnRender to delegate nine-layer sequential drawing
- Calling Update every frame to update all layers' internal states
- Computing BackgroundSourceRect (the control's rectangle in the background source coordinate system)
- Managing HasActiveAnimation state, determining whether continuous redraw is needed
- Forwarding mouse position, size change, and other events

The Composer holds a MaterialRenderContext object containing all rendering information: control size, corner radius, mouse position, timestamp, DeltaMs, performance preset, ambient colors (top/middle/bottom three colors), etc.

### 2.4 L4 Control Layer (Controls)

The control layer implements the IMaterialSurfaceHost interface to connect to the V5 pipeline:

```csharp
public interface IMaterialSurfaceHost
{
    double CornerRadius { get; }
    double Depth { get; }
}
```

Controls call `_composer.Render(dc)` in OnRender to delegate rendering. The UseV5Pipeline switch controls whether to use the V5 pipeline; when false, falls back to V4 AuroraGlassMaterial.

## 3. Nine-Layer Rendering System

V1.4.27.1 decomposes glass rendering into nine independent layers, rendered sequentially by Order.

### 3.1 ShadowLayer (Order=10)

Dual drop shadow layer. The outer layer uses a large-radius soft glow to simulate glass material light diffusion, while the inner layer uses a small-radius sharp shadow to enhance the glass boundary's three-dimensionality. Both shadows' colors and opacity are dynamically adjusted based on the current aurora theme color.

### 3.2 BlurLayer (Order=20)

True blurred background layer. This is the core of the frosted glass effect. It obtains visual content behind the control through AuroraMaterialPipeline's shared background sampling and applies GaussianBlurEffect for blur processing. The blur radius is controlled by the performance preset (8-32 pixels).

BlurLayer uses CroppedBitmap to crop the background sample by BackgroundSourceRect, avoiding controls sharing incorrect backgrounds. When BackgroundSourceRect is empty, the background is not a BitmapSource, or cropping fails, it returns without drawing, avoiding stretch distortion.

### 3.3 TintLayer (Order=50)

Ambient tint layer. V1.4.27.1's key improvement: changed from a single sampling point to top/middle/bottom three-point sampling, using LinearGradientBrush for vertical gradient. 4 GradientStops: top edge fade-out → upper-middle peak(topColor) → lower-middle peak(bottomColor) → bottom edge fade-out, with automatic linear interpolation between 0.35→0.65, simulating the aurora's top-to-bottom hue shift.

### 3.4 BodyLayer (Order=60)

Glass body layer. Draws rounded rectangle fill with a soft border overlay. V1.4.27.1 reduces border alpha from 80 to 35 and changes color from hard white to tint+40, eliminating the visible hard white circle.

### 3.5 NoiseLayer (Order=70)

Frosted noise layer. V1.4.27.1's key fix: atlas changed from increasing brightness (128→177) to per-frame independent random equal-brightness (fixed at 128), eliminating the brightness drop on loop. Frame switching changed from integer hard-cut to continuous frame position + blend factor cross-fade, eliminating abrupt jumps every 125ms.

### 3.6 FresnelLayer (Order=80)

Fresnel edge reflection layer. V1.4.27.1 increases radius from 0.5 to 0.62, widens transition zone from 15% (0.85→0.95→1.0) to 55% (0.45→0.72→0.9→1.0), and reduces peak alpha from 180 to 130, eliminating the hard elliptical ring caused by the narrow transition zone.

### 3.7 BevelLayer (Order=100)

Bevel thickness layer. Bright top + dark bottom simulates stereo edges, caching Frozen Brush and Pen to eliminate per-frame allocation.

### 3.8 ScanlineLayer (Order=120)

Scanline texture layer. Only enabled for Holographic style, draws horizontal scanlines to simulate CRT display effects.

### 3.9 GlowLayer (Order=130)

Hover outer glow layer. V1.4.27.1's core visual improvement:

- **4-Edge Uniform Highlight**: Changed from a single RadialGradientBrush (circular isolines) to 4 LinearGradientBrushes, each responsible for one edge fading toward the center, distributing isolines evenly along the rounded rectangular edge.
- **Ceremonial Transition**: Introduced _glowProgress progress variable (0..1) + EaseInOutCubic curve mapping, rate=1.5 (~3s for 99% completion), with gentle deceleration at both ends.
- **Zero-Allocation Hot Path**: 4 brushes created in EnsureCache, Render only updates GradientStop.Color.

## 4. Material Style Presets

V1.4.27.1 defines four differentiated material styles through MaterialStylePreset:

### 4.1 AuroraFluentGlass (Default)

Standard frosted glass style with all nine layers enabled. Blur radius 12px, noise animation speed 8fps, medium fresnel strength, medium hover glow strength. Suitable for most UI elements.

### 4.2 LiquidGlass

Liquid glass style with stronger fresnel and highlights. Blur radius 16px, elevated fresnel peak alpha, elevated glow strength. Suitable for highlighted interactive elements.

### 4.3 Mica

Mica style, skipping NoiseLayer (UseAnimatedNoise=false) and BlurLayer (UseTrueBackdropSampling=true), enabling DWM Acrylic backend. Suitable for window-level backgrounds.

### 4.4 Holographic

Holographic style, enabling ScanlineLayer. Blur radius 20px, medium scanline density, highest fresnel strength. Suitable for sci-fi themes.

Each style controls each layer's blur radius, opacity, animation speed, glow intensity, and other parameters through independent parameter presets.

## 5. Blur Backend Fallback Chain

V1.4.27.1 implements a five-level blur backend fallback chain, automatically selecting the optimal backend based on system capabilities.

### 5.1 DwmAcrylicBackend

Win11 DWM Acrylic/Mica backend. Designed as a window-level backend, requiring ApplyWindowBackdrop(window) to be called first to enable Win11 Mica/Acrylic, then returning null (letting the DWM system compositor provide blur).

V1.4.27.1's key fix: added _backdropApplied flag, requiring IsAvailable to be true. When Mica is not enabled, not selected, avoiding CaptureAndBlur returning null and causing blur to be missing.

### 5.2 ShaderEffectBackend

HLSL shader blur backend. Compiles HLSL Gaussian blur shaders through D3DCompiler, applied to the software rasterization path. Explicitly marked as CPU software rasterization implementation, avoiding GPU acceleration misrepresentation.

### 5.3 RtbBlurBackend

RenderTargetBitmap + BlurEffect backend. V1.4.27.0's only backend, serving as the third-level fallback in V1.4.27.1. Uses 1/2 resolution (960×540 max) + BlurRadius 2.5 (equivalent to 5) for blur background capture, throttled at 30fps.

### 5.4 Remote Session/VM Environment Handling

Remote sessions and virtual machine environments forcibly disable GPU backends (DwmAcrylic and ShaderEffect), falling back to RTB software blur, ensuring normal operation in environments without GPU acceleration.

## 7. Glass Visual Tuning

V1.4.27.1 conducted deep tuning of glass material visual details.

### 7.1 Edge Highlight "Four-Corner-Only" Fix

V1.4.27.0's GlowLayer used a single RadialGradientBrush (RadiusX=RadiusY=0.62), producing circular isolines. Inside a rounded rectangle, circular isolines only approach the edge near the four corners:
- Edge midpoints' normalized distance ≈ 0.806 → in transition zone, alpha = mid
- Corners' normalized distance ≈ 1.14 → exceeds 1.0, Pad takes peak alpha

Causing corners to be brighter than edge midpoints. V1.4.27.1 changes to 4 LinearGradientBrushes, each responsible for one edge fading toward the center (bandwidth = short side 40%), with isolines becoming "distance to nearest edge," evenly distributed along the rounded rectangular edge.

### 7.2 Glass Color Vertical Gradient

V1.4.27.0 sampled only the top Y position, using the same AmbientColor for the entire glass. V1.4.27.1 samples three Y positions (top/middle/bottom) (3 reflection calls ≈ 0.003ms/frame), with TintLayer using LinearGradientBrush for 4-GradientStop vertical gradient.

### 7.3 Edge Hard Ring Fix

V1.4.27.0's BodyLayer 1px white border (alpha=80) + FresnelLayer 15% narrow transition (peak=216) caused visible hard rings. V1.4.27.1 reduces BodyLayer alpha to 35, changes color to tint+40, widens FresnelLayer transition to 55%, and reduces peak to 130.

### 7.4 Noise Brightness Jump Fix

V1.4.27.0's 8-frame atlas with increasing brightness + hard-cut frame switching caused per-second brightness drops. V1.4.27.1 changes to equal-brightness independent random generation + continuous frame position cross-fade.

### 7.5 Aurora Color Weighted Blending

V1.4.27.0's SampleAuroraColorAt discrete layer selection caused instant color jumps at layer transitions. V1.4.27.1 changes to all-layer weighted RGB accumulation normalization, with each layer weighted by influence (raw²), achieving smooth inter-layer transitions.

## 8. Hover Ceremony Design

V1.4.27.1 designed the hover transition with careful ceremony.

### 8.1 EaseInOutCubic Easing Curve

Changed from pure exponential smoothing (rate=9.0, 0.5s completion) to EaseInOutCubic curve (rate=1.5, 3s for 99% completion):

```
eased = t < 0.5 ? 4*t*t*t : 1 - Math.Pow(-2*t + 2, 3) / 2
```

Curve characteristics:
- t=0.2: eased=0.032 (only 3.2% strength, nearly imperceptible)
- t=0.5: eased=0.5 (midpoint, linear progression)
- t=0.8: eased=0.968 (96.8%, graceful convergence)
- Entry and exit are symmetric, equally gentle

### 8.2 Animation Speed Parameter Effectiveness Fix

V1.4.27.0 had two defects causing the rate parameter to be ineffective:

1. **GlowLayer fallback**: When DeltaMs<=0, used fixed smoothFactor=0.15 (equivalent to rate=9.0), bypassing the rate parameter
2. **Composer first-frame DeltaMs transient**: _lastTimeMs=0 caused first-frame DeltaMs of hundreds of milliseconds, smoothFactor≈1.0, skipping the entire transition

V1.4.27.1's fixes:
- Fallback also calculates based on rate (assuming 60fps)
- DeltaMs clamped to 100ms upper limit

### 8.3 SpecularLayer Removal

V1.4.27.0's SpecularLayer implemented a white highlight following the mouse position, but the visual effect was not noticeable in actual use. V1.4.27.1 completely removes this layer (including file, registration, and HasActiveAnimation branches), with hover feedback carried entirely by GlowLayer, making the visual expression purer.

## 9. Defect Fixes

### 9.1 Window Switching Timing Race

V1.4.27.0's AuroraStarfield.Unloaded unconditionally called ClearBackgroundSource(). In the startup chain splash→permission window→mainformview→pro, the old window's Unloaded could fire after the new window's SetBackgroundSource, incorrectly clearing the background source already registered by the new window.

V1.4.27.1's ClearBackgroundSource adds an optional source parameter, only clearing when the currently registered background source is itself. AuroraStarfield.Unloaded passes this.

### 9.2 DwmAcrylicBackend Misselection

V1.4.27.0's IsAvailable only probed platform capabilities without checking whether Mica was enabled. Windows without Mica enabled selected this backend, where CaptureAndBlur returned null and BlurLayer skipped rendering.

V1.4.27.1 adds a _backdropApplied flag, falling back to ShaderEffect or RTB when Mica is not enabled.

### 9.3 BlurLayer Background Stretch

V1.4.27.0's degradation path stretched the entire starfield sample with Stretch=Fill to the surface rectangle, causing aspect ratio distortion. V1.4.27.1 returns without drawing when there is no valid BackgroundSourceRect, and adds a PointToScreen + PointFromScreen fallback in Composer for TransformToVisual failures.

### 9.4 PRO Mode Export Folder Path

V1.4.27.0's ShowUserLogs used MyDocuments\AURORA\UserLogs, inconsistent with the PowerShell script's $PSScriptRoot\..\..\UserLogs. V1.4.27.1 implements three-level path resolution: ScriptsRoot up one level + UserLogs → exe directory up 6 levels searching → MyDocuments fallback.

## 10. Performance Optimization

### 10.1 Zero-Allocation Hot Path

All rendering layers implement zero-allocation hot paths. GlowLayer's 4 brushes are created in EnsureCache, with Render only updating GradientStop.Color (value type). BodyLayer and BevelLayer cache Frozen Brush and Pen. NoiseLayer's dual brushes are created in EnsureCache.

### 10.2 Blur Background 30fps Throttling

Blur background's RenderTargetBitmap.Render is limited to 30fps (SharedBgUpdateMs=33), using 1/2 resolution (CaptureScale=0.5, 960×540 max, BlurRadius=2.5).

### 10.3 Rendering Subscription Management

CompositionTarget.Rendering subscription unsubscribes when Composer count reaches zero, preventing idle consumption. AuroraStarfield resubscribes on Loaded event, preventing animation stall after Tab switching.

### 10.4 Static Button Render Skip

AuroraButton skips OnRender for static buttons (no hover/press/ripple/spring/glare and disabledSettled), avoiding unnecessary redraws.

## 12. Known Limitations

### 12.1 ShaderEffectBackend is CPU Software Rasterization

ShaderEffectBackend uses RenderTargetBitmap.Render for software rasterization, and performance may not match BlurEffect. Explicitly marked as CPU implementation, avoiding GPU acceleration misrepresentation.

### 12.2 D3DCompiler P/Invoke Limitations

D3DCompiler's P/Invoke requires correct handling of UTF-8 encoding and 64-bit SIZE_T, preventing memory overflow and truncation. ID3DBlob.GetBufferSize returns 64-bit SIZE_T, requiring C# declaration as long type.

### 12.3 Mica Backend Requires Window-Level Enablement

DwmAcrylicBackend is a window-level backend, requiring ApplyWindowBackdrop to be called first to enable Mica. Windows without Mica enabled fall back to RTB software blur, unable to leverage DWM native Acrylic capability.
